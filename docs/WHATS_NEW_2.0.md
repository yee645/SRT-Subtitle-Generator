# 2.0 有什麼新東西

**如果你是從 v1.51.0 更新上來的，這一份就是你要看的。**

2.0 之前的每一版（v1.52.0 ~ v1.52.3）都標記為測試版、不推自動更新，所以
你的程式很可能一直停在 **v1.51.0**。這代表更新到 2.0 的那一刻，中間累積
的所有改動會**一次全部到齊**——這份文件涵蓋的就是 `1.51.0 → 2.0.0` 之間
的全部內容，不只是最後一版。

---

## 一句話

**主視窗從「一整頁設定」變成「四個階段」，做一支影片的每一步都照順序排
好；做出來的東西會自動流到下一步，不必再自己記路徑、複製貼上。**

---

## 1. 主視窗改成四個階段

以前開啟程式看到的是一整頁設定，而且**「開始生成字幕」這顆主按鈕根本不
在畫面上**——它在 y=826 的位置，而預設視窗高度只有 800。新手第一次打開，
看到的是設定表單，沒有任何可按的主要動作。

現在是四個頁籤，順序就是做一支影片的順序：

| 階段 | 裡面有什麼 |
|------|-----------|
| **① 素材與剪輯** | 選檔、匯入既有字幕、審片助手、剪停頓、剪重複片段 |
| **② 字幕** | 設定＋主動作＋字幕清單＋樣式與即時預覽（預設停在這裡） |
| **③ 健檢中心** | 影片、字幕、封面、發佈文字的所有健檢一次跑完 |
| **④ 輸出與發佈** | 輸出設定、完成輸出、成品加工、發佈資料 |

主按鈕現在在 **y=131**，一開啟就看得到。

頂端還有一條跨階段的**工作檔案列**，隨時顯示目前在處理哪支影片、有幾句
字幕。

**原本工具列上的 11 顆按鈕全部搬進對應階段**，一顆都沒有拿掉。第一次開
啟新版時程式會跳一張「新版介面速覽」對照表告訴你各項功能搬到哪裡（可勾
「不再顯示」）；完整版見 [`MIGRATION_1x_TO_2.0.md`](MIGRATION_1x_TO_2.0.md)。

## 2. 「一鍵完成」拆成兩顆——為了讓你有機會校對

舊版的〔一鍵完成（生成＋匯出＋燒錄）〕會**一路衝到底**：生成完字幕直接
匯出、直接燒錄。聽起來很方便，實際上等於**沒有任何校對的機會就把錯字燒
進影片**——而語音轉寫一定會有錯字。

現在是並排的兩顆：

```
[開始生成字幕]  [完成輸出（依輸出設定）]
```

中間那段空白，就是校對、健檢、翻譯的位置。**不需要校對的話，連按兩顆，
結果和以前完全一樣。**

**一次處理很多支影片**：選到兩個以上檔案時，動作列會自動多出
〔**批次一鍵完成**〕，行為與舊版一致（批次本來就不會逐支校對）。只選一
個檔案時這顆不會出現——一顆永遠灰著的按鈕只會讓人一直想「要怎樣才能按
它」。

## 3. 輸出區：按之前就知道會產出什麼

舊版「同一個匯出 SRT」的概念散在三個地方、行為各不相同：一處要你先勾
選、按了不問路徑；一處是按鈕、按了跳存檔框——而介面從來沒說過它們差在
哪裡。

現在階段④只有一個「輸出」框，由上而下就是你的決策順序：

```
輸出
  匯出 SRT＋燒錄硬字幕影片 → D:\成品      ← 勾選一改，這句話立刻跟著變
  [完成輸出（依輸出設定）]
  ──────────────────────────────
  輸出設定
  自動匯出: ☑SRT ☐VTT ☐ASS ☐TXT
  ☑燒錄硬字幕影片   ☐燒錄時響度正規化
  輸出資料夾: [__________]
  ──────────────────────────────
  只做單獨一件事
  （這一列會另外問你要存到哪裡；上面的〔完成輸出〕全程不問路徑）
  [匯出 SRT][匯出 VTT][匯出 ASS][匯出 TXT][燒錄字幕到影片]
```

最上面那句話會告訴你**這次按下去會產出什麼、放到哪裡**。

## 4. 做出來的東西會自動流到下一步

這是 2.0 改動最大、也最省事的一塊。

舊版每做出一樣東西，就只跳一個訊息框報路徑然後結束。最誇張的例子是健檢
中心修完音訊會說「修復版已輸出：`D:\片_修復.mp4`」，訊息裡甚至寫著「也
可對輸出版再跑一次健檢比對」——**但介面完全沒有給你做得到這件事的路
徑**，你得自己記住路徑、回主視窗重新選檔案。

現在：

| 你做了什麼 | 2.0 會怎樣 |
|-----------|-----------|
| 審片助手輸出粗剪／精彩合輯 | 問你要不要設為「目前影片」，接手後直接上字幕、健檢 |
| 健檢中心修出修復版 | 問你要不要接手；接手後檢查對象同步換掉，**再按一次〔開始健檢〕就是修復前後的比對** |
| 燒錄出成品 | 記進來歷；問你要不要接手（接著配樂、套版就吃這支） |
| 審片產生章節草稿 | 剪貼簿照舊，**另外**帶進階段④「發佈資料」 |
| 審片產生發佈包／封面候選 | 標題、說明欄、標籤、章節、候選圖全部自動流進階段④ |

階段④的「發佈資料」一顆〔**送健檢中心**〕，就把整包填進健檢中心的檢查
對象——不必再一段一段複製貼上。

**工作檔案列還會顯示這支影片是怎麼來的：**

```
目前影片：原始素材 訪談.mp4 → 粗剪 → 修復版 → 燒錄版（目前）
```

> **為什麼是「問你」而不是自動換掉？** 剪輯和修復都是可能改壞的處理
> （音訊被動過濾鏡、片段被剪掉），你本來就該先播放確認再決定要不要沿
> 用。自動換掉會讓你沒聽過的版本悄悄變成後面所有步驟的輸入。
>
> **換影片時字幕清單不會被清掉**，但會提醒你時間軸可能已經對不上——那
> 是你的校對成果，程式不會替你丟掉，也不會假裝它一定還能用。

## 5. 健檢中心：六個視窗併成一個

v1.50–v1.51 已經把上片前健檢、字幕健檢、上片前總體檢、發佈健檢、封面健
檢、章節健檢六個視窗併成一個「健檢中心」：

- 檢查對象（影片／字幕／封面圖／發佈文字／系列影片）**全部選填，填什麼
  檢什麼**
- **18 項檢查**一次跑完，產出單一分級報告
- **9 個一鍵修復**，可修的發現旁邊就是修復按鈕

## 6. 自動修剪：剪停頓與剪重複片段

兩個功能現在是同一個「自動修剪」視窗的兩個分頁（兩個入口都保留，各自開
到對應分頁）。

兩者的個性刻意保留不同：

- **剪停頓（依字幕）**——剪的是沒人講話的空檔，誤判成本低，所以是預覽後
  直接輸出。
- **剪重複片段**——動的是**實際講話內容**，刻意重複的口號、報數測試麥克
  風都可能被誤判，所以是**列出候選、逐項勾選確認、才剪**。

剪出來的影片也會問你要不要設為「目前影片」。

## 7. 即時查譯（外文素材）

選取逐字稿或字幕編輯框裡的一段外文，**鬆開滑鼠就翻成中文**，附關鍵詞解
說，生字本可匯出 CSV。頂列常駐入口〔即時查譯〕。

需要 OpenAI API 金鑰；沒有金鑰時開窗會直接說明，不會讓你按了才發現。

> **做得到與做不到**：目前是**本程式內的選取**才會翻譯。Windows 沒有讓
> 外部程式讀取「你在別的軟體裡選了什麼」的通用 API，零依賴下更沒有，所
> 以「在任何軟體裡選取都能翻」這件事現階段做不到。剪貼簿版（複製即翻
> 譯）是評估中的下一階段。

## 8. 其他看得到的改善

- **深色主題完整了**：所有數字輸入框都換成主題版，深色下不再出現刺眼的
  白框。
- **字幕清單的時間欄放得下完整時間碼**了（以前每一列的結束時間都被截
  掉）。
- **視窗縮到最小尺寸時右欄自動收合**讓出空間，主動作與字幕清單永遠可見。

## 這次省了多少（實測）

以同一個情境實走：一支已剪好的影片 → 產出「燒好字幕的影片 ＋ SRT ＋ 章
節/發佈資訊/封面都檢過 ＋ 總體檢通過」。

| | v1.x | 2.0 |
|---|---|---|
| 點擊 | 43–46 次 | **31 次**（−31%） |
| 開啟視窗 | 17–19 個 | **7 個**（−61%） |
| 貼上 | 4 次 | 4 次 |
| 主按鈕位置 | y=826（畫面外，要捲動找） | y=131（一開啟就看得到） |

**誠實說明**：這個數字比當初規劃的預估（20 次上下、3–5 個視窗）差，原因
有二——

1. **校對那一段完全沒被改到**（9 擊 3 窗）。逐句修字是內容工作，不是動線
   問題，介面重構省不到它。
2. **健檢中心還沒有整個內嵌成頁籤內容**，階段③目前仍然只是入口，按下去
   開的還是獨立視窗。這一項是刻意延後的骨架級大改。

換句話說：**結構性的浪費已經清掉了，剩下的 31 次裡有 17 次是內容工作本
身。**

## 升級須知

- **設定會沿用**，不必重設。勾選過的輸出格式、門檻、樣式組合都還在。
- 第一次開啟會跳一次「新版介面速覽」，可勾「不再顯示」。
- 影片的「來歷」（世代鏈）**只記在這次開啟期間**，關掉程式就忘掉——它記
  的是絕對路徑，存起來之後你搬動或刪除檔案只會留下一串指向空氣的紀錄。
- **CLI 完全相容**：`cli.py` 的旗標全部沿用，沒有改名也沒有移除。
- `config.json` 的既有欄位沒有刪改，只有新增。

## 沒有變的事

所有核心能力一項不少：轉寫、文字稿對齊、手動字幕、智慧斷句、字幕樣式與
即時預覽、硬字幕燒錄、翻譯與雙語字幕、多語字幕包、審片助手（精彩片段／
冷場／重複拍攝／粗剪／EDL／直式短片／封面候選／發佈包）、配樂助手（自動
閃避）、品牌套版、音訊轉影片、以及 18 項健檢與 9 項一鍵修復。
