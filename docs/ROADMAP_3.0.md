# SRT 字幕生成器 3.0 工作清單

這份文件定義 **3.0 的目標**。2.x 的工作清單仍在
[`docs/ROADMAP_2.0.md`](ROADMAP_2.0.md)，**它還沒做完，優先權仍然在它上面**；
本文件是等那邊收尾之後才開工的題目。

## 3.0 是什麼

使用者的原話（2026-09-23）：

> 「繼續開發，可繼續搜尋和制訂更新內容，並將 3.0 的目標訂定在，期望將本
> 軟體做成如 adobe premiere 等主流剪輯軟體的水準。」

## 先講清楚：哪一部分做得到、哪一部分做不到

這一節不是推託，是**為了不讓 3.0 變成一張兌現不了的支票**。使用者要的是
「主流剪輯軟體的水準」，那就得先分清楚這句話裡哪些是我們補得起來的功
能差距、哪些是被技術底座卡死的。以下每一條都有實測數字或程式碼依據，
不是憑印象。

### 底座的硬限制（不是懶，是真的做不到）

本專案的兩條地基是 **Tkinter 介面**與**零第三方 Python 依賴**（只有
`sv_ttk` 被打包進 exe）。這兩條決定了：

| Premiere 有、我們做不到 | 為什麼 |
|---|---|
| **即時播放（含聲音同步）** | Tk 沒有影片元件。唯一的畫面來源是 ffmpeg 抽幀 → `PhotoImage`。實測抽一張 480px 寬的幀要 **81~163 ms**，等於上限約 **8~12 fps 且沒有聲音**。那是「拖曳時看得到畫面」，不是播放。 |
| **GPU 合成、即時特效預覽** | 沒有 GPU 存取層，也不可能在零依賴下寫一個。 |
| **多軌疊加、去背、遮罩、關鍵影格動畫** | ffmpeg 濾鏡理論上做得到，但**沒有即時預覽就沒有人調得動**——調一個參數等十幾秒輸出再看，不是剪輯，是猜謎。 |
| **專業調色（曲線、色輪、示波器）** | 同上，而且示波器要逐幀取像素，Tkinter 畫不動。 |
| **音訊混音台、即時效果鏈** | 沒有音訊輸出層，聽不到就調不了。 |

**結論：3.0 不會、也不應該宣稱「變成 Premiere」。** 把這句話寫死在這
裡，是為了讓之後每一晚的自己不要偷偷往那個方向承諾。

### 但差距的另一半是真的補得起來（而且那一半才是痛點）

實測過才敢這樣寫。用一支 5 分鐘 1280x720 的影片量到的數字：

| 量什麼 | 數字 | 意義 |
|---|---|---|
| 跳到任意時間點抽一張幀 | **81 ms / 81 ms / 130 ms**（第 10、150、290 秒） | **不隨位置變長**（`-ss` 放在 `-i` 前面是輸入端 seek）。拖時間軸即時換畫面是可行的。 |
| `PhotoImage` 載入那張 PNG | **2~7 ms** | 顯示不是瓶頸，Tk 8.6 原生吃 PNG，零依賴。 |
| 整支片的縮圖條（每 2 秒一張，96px 寬，單次 ffmpeg） | **150 張 / 2.5 秒**（17 ms/張） | 時間軸底下那條「膠卷」做得出來，而且可以快取。 |
| 整支片的波形資料（8 kHz 單聲道 PCM → 峰值） | 解碼 **0.96 秒**、算 2000 個峰值 **124 ms** | 時間軸上的波形圖做得出來，**這是目前完全沒有的東西**。 |

換算到一小時的素材（**這是線性外推，不是實測**）：膠卷約 30 秒、波形約
12 秒，兩者都可以背景跑、可以存檔快取。

### 真正的差距在哪：使用者現在為了什麼事情要離開這個工具

盤點現有程式碼（`subtitle/` 共 57 個模組）之後，差距很具體：

**已經有了，而且是 Premiere 沒有的**：逐字稿審片（`subtitle/review.py`）、
全片停頓自動跳剪（`subtitle/jumpcut.py`）、重複拍攝偵測與剪除
（`subtitle/retakes.py`）、短影音切片（`subtitle/shorts.py`）、字幕樣式
與燒錄、多語字幕包、十幾項上架前健檢。這些是本工具的強項，**3.0 不能為
了追像 Premiere 而把它們稀釋掉**。

**缺的是「看得到、動得了」那一層**：

1. **所有的剪都是盲剪。** `jumpcut.py` 算出剪點之後直接輸出成片，使用者
   從頭到尾**沒有機會看到剪在哪裡**，更不用說微調。`retakes.py` 好一點
   （列出候選讓人勾選），但勾選的也只是文字，不是畫面。
2. **沒有時間軸。** 整個 `gui/` 目前連一次 `PhotoImage` 都沒用過——這個
   程式從來沒有在畫面上顯示過任何一張圖。`gui/preview_panel.py` 的「預
   覽」是用 Canvas **畫出來的假畫面**，只為了對照字幕樣式，不是影片。
3. **沒有轉場。** 全庫 grep `xfade` **零命中**。接片只有
   `branding.py`（片頭片尾）與 `jumpcut.py`（trim+concat）兩處硬切。
4. **不能拼多支素材。** 所有流程都假設「一支輸入影片」。A-roll 接 B-roll
   這種最基本的事做不到，使用者只能去開 Premiere。
5. **波形只是輸出物，不是工具。** `audiovis.py` 用 ffmpeg 的
   `showwaves` 把波形**算成一支影片**，`audiocheck.py` 拿它偵測爆音——
   但使用者在編輯的時候看不到波形。

第 1 項是最關鍵的：`subtitle/review.py` 的說明裡已經自己寫著匯出 EDL
「匯入 Premiere / DaVinci Resolve 繼續精剪」——**那行字就是差距的位
置**，我們算完就把人送走了。

## 3.0 的目標（重新表述）

> **讓創作者不必為了「把剪點看一眼、挪一下」而離開這個工具。**
>
> 把本工具已經會自動算出來的那些剪接決定——審片取捨、跳剪停頓、剪重複
> 片段、切短影音——從「算完直接輸出」變成**看得見、挪得動、接得起來**：
> 一張有畫面縮圖與聲音波形的時間軸、可以拖動的剪點、可以串接的多段素
> 材、以及最基本的轉場與畫面調整。
>
> **不追求**即時播放、GPU 特效、多軌合成、專業調色。那些是 Premiere 的
> 本業，也是本工具的底座不支援的。3.0 追求的是**在「自動算 + 人工確認」
> 這條路上做到專業水準**，而不是把 Premiere 重寫一次。

這樣的 3.0 對使用者的具體承諾只有一句話：**剪完之前你會看到它剪在哪
裡，而且你改得動。**

## 工作清單（草案，開工前再逐項細化）

排序原則沿用 2.x：**每一步都要能單獨出貨、能單獨回退**，先做能立刻讓使
用者看見的，再做底層擴充。

| # | 題目 | 為什麼排這裡 | 狀態 |
|---|---|---|---|
| 1 | **`subtitle/filmstrip.py` + `subtitle/waveform.py`**：抽幀縮圖條與波形峰值，帶快取，零 GUI 依賴 | 時間軸的兩種資料來源，先把核心層量好測好 | 待做 |
| 2 | **`gui/timeline.py`**：Canvas 時間軸元件（縮圖條、波形、游標、選取區、剪點標記） | 這是 3.0 的門面，第 1 項好了就能做 | 待做 |
| 3 | **剪點可視化與微調**：`jumpcut` / `retakes` / `review` 的結果畫到時間軸上，剪點可拖曳、可單獨停用 | 把「盲剪」變成「看得見的剪」——差距清單第 1 項 | 待做 |
| 4 | **多段素材拼接**：`subtitle/assemble.py`，多支輸入按順序接成一支，字幕時間軸一併平移 | A-roll/B-roll，也是轉場的前提 | 待做 |
| 5 | **轉場**：ffmpeg `xfade` / `acrossfade`，先只做最常用的幾種（淡入淡出、溶接、黑場） | 接得起來之後才有地方放轉場 | 待做 |
| 6 | **基本畫面調整**：亮度／對比／飽和度／裁切／旋轉，套用前用抽幀做「前後對照」靜態預覽 | 沒有即時預覽，但靜態對照就夠用了 | 待做 |
| 7 | **專案檔**：把整組剪接決定存成可重開的檔案 | 一旦剪接決定變多，不能每次重來 | 待做 |
| 8 | 文件與四個產出物（`docs/WHATS_NEW_3.0.md`、CHANGELOG、README、`gui/whatsnew_dialog.py`） | 沿用 2.x 的轉正前置條件 | 待做 |

**每一項開工前都要先做一次調研與實測**，照 2.x 已經驗證有效的做法（使用
者 2026-09-18 指示「先做調研再動手」）。上面的數字只證明「底座撐得住」，
不代表每一項的細節都已經想清楚。

## 明確不做的事（寫下來，之後不要再重新評估）

- **即時播放器**（含聲音）。上限 8~12 fps 無聲，做出來只會讓人以為壞了。
- **GPU 特效、即時濾鏡預覽、關鍵影格動畫。**
- **多軌時間軸合成**（畫中畫、疊圖層）。第 4 項的「拼接」是單軌串接，
  不是多軌疊加。
- **專業調色與音訊混音台。**
- **引入第三方 Python 套件來繞過以上限制**（`opencv`、`Pillow`、
  `numpy`、`pyav`…）。零依賴是既定約束，見 2.0 文件「每晚的紀律」。
  外部**執行檔**（ffmpeg、tesseract 那個模式）不在此限。
