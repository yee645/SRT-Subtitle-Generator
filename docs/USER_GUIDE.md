# 使用說明

介面、操作流程、設定與常見問題。各功能的詳細介紹見 [功能詳解](FEATURES.md)，回 [README](../README.md)。

## 介面長什麼樣（v1.52.1 起）

主視窗是**四個階段頁籤**，順序就是做一支影片的順序：

| 頁籤 | 裡面有什麼 |
|------|-----------|
| **① 素材與剪輯** | 選檔、匯入既有字幕、審片助手、剪停頓（依字幕）、剪重複片段 |
| **② 字幕** | 設定（左欄）＋主動作與字幕清單（中欄）＋樣式與即時預覽（右欄）——預設停在這裡 |
| **③ 健檢中心** | 爆音、音量、畫質、字幕品質、發佈資訊、封面、章節等健檢一次跑完（v2.2 起健檢中心整個就在這個頁籤裡，不再另開視窗） |
| **④ 輸出與發佈** | 「輸出」框（輸出設定＋完成輸出＋逐格式匯出）、成品加工（配樂助手／品牌套版） |

頂端有一條跨階段的**工作檔案列**（目前影片＋字幕句數），四個階段共用
同一份素材。**v1.52.1 之前的工具列已經取消**，原本工具列上的功能都搬
進了對應的階段——第一次開啟新版時程式會跳一張「新版介面速覽」對照表
告訴你各項功能搬到哪裡，看過可勾「不再顯示」。

> 舊版說明中提到「工具列的某某按鈕」時，請對照上表到相應階段找。完整的
> 1.x → 2.0 對照表見 **[`docs/MIGRATION_1x_TO_2.0.md`](MIGRATION_1x_TO_2.0.md)**
> ——包含工具列 11 顆的去向、四個改名，以及四項「不只是搬家而是行為變
> 了」的說明。

## 快速上手（v1.52.1 起）

日常上字幕的流程：

1. **選檔**：在頂端工作檔案列或階段①按「瀏覽...」選擇影片（可按住
   Ctrl / Shift 一次選多個檔案批次處理）。
2. **勾選輸出**：到階段④「輸出與發佈」的「輸出設定」勾選要匯出的格式
   （SRT／VTT／ASS／TXT），需要硬字幕影片就勾「燒錄硬字幕影片」。這些
   勾選會被記憶，之後不必再設定；框最上方那句話會直接告訴你「這次會輸
   出什麼、放到哪裡」。
3. **按〔開始生成字幕〕**：產生字幕並載入清單。
4. **（建議）校對**：在階段②清單雙擊修字，或到階段③跑一次健檢。
5. **按〔完成輸出（依輸出設定）〕**：依上面的勾選匯出／燒錄，全程不跳
   存檔對話框。

> **為什麼是兩顆按鈕？** v1.52.1 之前的〔一鍵完成〕會生成完直接匯出並
> 燒錄，等於沒有校對的機會就把錯字燒進影片。拆成兩顆之後，中間那段就
> 是校對的位置。不需要校對的話，連按兩顆，結果和以前完全一樣。

**一次處理很多支影片**：選到兩個以上檔案時，動作列會自動多出
〔**批次一鍵完成**〕，行為與舊版的〔一鍵完成〕一致（批次本來就不會逐
支校對）。只選一個檔案時這顆不會出現。

輸出規則：

- 輸出檔自動以來源檔名命名：`影片.mp4` → `影片.srt`、`影片_subtitled.mp4`。
- 預設輸出到來源檔所在資料夾；也可在「輸出設定」指定固定的輸出資料夾。
- 同名檔已存在時自動改名為 `影片 (1).srt`，不會覆蓋舊檔。
- 批次處理時逐檔顯示進度（`[2/5] 影片B.mp4：...`），單一檔案失敗不會中斷整批，結束後會列出成功與失敗清單。
- 完成後最後一個檔案的字幕會載入清單，可直接檢視、微調後用下方按鈕重新匯出。

**批次跑「文字稿對齊」**：把每部影片的文字稿存成旁邊同名的 `.txt`（如 `演講.mp4` 配 `演講.txt`），程式會自動帶入，不必逐一貼上。

### 最快的用法：把檔案拖到 exe 圖示上

在檔案總管把一個或多個影片**直接拖曳到 `SRT-Subtitle-Generator.exe` 圖示上**，程式會依記憶的自動化設定靜默跑完整條流程，結束後以視窗回報每個檔案的輸出結果——連程式視窗都不用開。

### 3.0 預覽版（開發中，從原始碼執行）

3.0 會把介面換成 Qt（PySide6）並加上真的播放器與時間軸，進度見
[`docs/ROADMAP_3.0.md`](ROADMAP_3.0.md)。目前已有四個階段頁籤與深淺主題、〔② 字幕〕頁的
播放器與時間軸，以及〔③ 健檢中心〕；還沒搬過去的功能請照舊用一般版。想先看看的話：

```
pip install PySide6
python main.py --qt
```

打包好的 exe **目前不含** Qt 版；不加 `--qt` 就是一般版，兩者讀同一份設定檔。

### 命令列批次模式（進階）

不開視窗也能跑同一條自動流程，設定沿用 `config.json`（在 GUI 調好一次即可）：

```
python main.py 影片1.mp4 影片2.mp4          # 依記憶的自動化設定批次處理
python main.py --burn 影片.mp4              # 本次強制燒錄硬字幕
python main.py --formats srt,ass 影片.mp4   # 本次改匯出 SRT 與 ASS
python main.py --mode align 演講.mp4        # 文字稿對齊（文字稿放在同名 .txt）
python main.py --output-dir D:\out 影片.mp4 # 本次輸出到指定資料夾
python main.py --audiocheck 影片.mp4        # 上片前音訊健檢（免轉錄）
python main.py --videocheck 影片.mp4        # 影片畫質健檢＋頭尾廢秒（免轉錄）
python main.py --thumbnails 影片.mp4        # 封面候選圖（免轉錄，均勻取樣）
python main.py --subs 影片.srt --burn 影片.mp4   # 既有字幕直接燒錄（免轉錄，v1.19 起）
python main.py --subcheck 影片.mp4          # 字幕健檢：CPS／行數，可與其他模式併用（v1.20 起）
python main.py --punctcheck 影片.mp4        # 中文字幕標點規範（v1.47 起）；加 --punctfix 另存規範版
python main.py --adcheck 影片.mp4           # 廣告友善度自查：黃標風險預檢（v1.29 起）
python main.py --subs 舊字幕.srt --synccheck --syncfix 影片.mp4  # 字幕同步檢查＋校正（v1.30 起）
python main.py --seriescheck EP01.mp4 EP02.mp4 EP03.mp4  # 系列一致性：比對整批彼此（v1.31 起）
python main.py --chaptercheck 章節.txt --chapterfix 影片.mp4  # YouTube 章節健檢＋一鍵修正（v1.32 起）
python main.py --hookcheck 影片.mp4         # 開場健檢：多久才進正題（v1.33 起）
python main.py --pacecheck 影片.mp4         # 剪輯節奏健檢：畫面太久沒變化（v1.34 起）
python main.py --thumbcheck 封面1.png 封面2.png  # 封面健檢＋候選排序（v1.35 起）
python main.py --publishcheck 發佈資訊.txt 影片.mp4  # 發佈資訊健檢（v1.36 起）
python main.py --legibility 影片.mp4        # 字幕可讀性健檢（v1.37 起）
python main.py --preflight 影片.mp4         # 上片前總體檢：一次跑完（v1.38 起）
python main.py --endscreen 影片.mp4         # 片尾空間健檢（v1.39 起）
python main.py --sponsorcheck 影片.mp4      # 工商揭露健檢（v1.40 起）
python main.py --termcheck 影片.mp4         # 術語一致性檢查（v1.41 起）
python main.py --shorts 長片.mp4            # 自動挑段輸出多支直式短片（v1.42 起）
python main.py --multilang 影片.mp4         # 多語字幕包（v1.43 起）
python main.py --beatcheck --music 配樂.mp3 影片.mp4  # 節拍分析＋剪點對齊（v1.44 起）
python main.py --multilang --languages en,ja,ko --subs 母帶.srt 影片.mp4
python main.py --shorts --shorts-count 5 *.mp4  # 批次：每支各出 5 支短片
python main.py --termcheck --termfix 影片.mp4  # 順便一鍵統一寫法
```

命令列旗標僅影響本次執行，不會改寫記憶的設定。適合搭配排程或一次處理整批檔案。

## 一、下載與安裝

1. 前往本專案的 **Releases** 頁面，下載最新版的 `SRT-Subtitle-Generator.exe`。
2. 此為免安裝程式，下載後直接雙擊即可執行。
3. 首次執行會在程式所在資料夾自動建立 `config.json`（保存個人化設定）。

### 必要元件：ffmpeg（v1.12.0 起可一鍵自動安裝）

本程式的音訊解碼與語音轉錄皆依賴 **ffmpeg**。**最簡單的安裝方式：什麼都不用先做**——程式偵測不到 ffmpeg 時（審片助手、音訊健檢等視窗會顯示黃色提示條，錯誤視窗也會提供按鈕），按「**自動安裝 ffmpeg**」即可：

- 程式自動下載（約 80~100 MB，只需一次）並安裝到程式自己的資料夾
- **免管理員權限、不需要設定 PATH**，裝完立即可用、下次啟動自動生效

偏好手動安裝（或公司網路擋下載）時：

1. 至 [gyan.dev](https://www.gyan.dev/ffmpeg/builds/) 下載 release-essentials 壓縮檔。
2. 把其中的 `ffmpeg.exe` 與 `ffprobe.exe` 放到程式資料夾的 `tools\ffmpeg\bin\` 內（免設定 PATH）；或依傳統做法把 `bin` 資料夾加入系統環境變數 `PATH`。
3. 重新開啟本程式即可。

未安裝 ffmpeg 時，「文字稿對齊」「本地轉錄」「字幕燒錄」「粗剪／精彩合輯輸出」「音訊健檢」「封面候選」與審片助手的音量能量分析皆無法使用（審片的精彩偵測會退化為純文字訊號）。

### 自動更新

本程式（v1.1.0 起）內建自動更新：

- 每次啟動時會於背景向 GitHub 檢查是否有新版本。
- 偵測到新版時會跳出視窗詢問，同意後自動下載並替換程式檔。
- 更新完成後，關閉並重新開啟程式即可套用新版。
- 無網路或連線失敗時會自動略過，不影響程式使用。

#### 2.0 已經發佈

`v1.52.0` ~ `v1.52.3` 是 2.0 重構期間的測試版，一律不推自動更新，所以多數
使用者一直停在 `v1.51.0`。**更新到 2.0 時，中間累積的所有改動會一次全部到
齊**——完整說明見 **[`docs/WHATS_NEW_2.0.md`](WHATS_NEW_2.0.md)**，

#### v2.2.0：健檢中心搬進主視窗

## 二、三種運作模式

舊版介面上這三種依序叫「模式一／模式二／模式三」，v2.3.1 起改成直接寫它做什麼：〔語音轉寫〕〔文字稿對齊〕〔手動輸入〕。

### 語音轉寫

匯入影片／音訊檔，由系統自動產生逐字稿與時間軸。轉錄引擎有兩種選擇：

- **OpenAI API**（免安裝，最簡單）
- **本地 Whisper**（免費、可離線，但需自行安裝，見下方第三節）

### 文字稿對齊

貼上現成的逐字稿，系統會借用語音辨識取得音訊中「人聲」的時間軸（會自動忽略背景音樂），再把文字稿依語音長度與停頓分配到對應的時間點，讓字幕只落在有人聲的區段。

由於改用語音辨識偵測人聲，此模式同樣需要可用的語音辨識引擎（本地 Whisper 或 OpenAI API），設定方式與「語音轉寫」相同，見下方第三節。

### 手動輸入

不經語音辨識，從零開始手動建立字幕：按「新增字幕」逐句輸入文字與起訖時間，適合無人聲素材、歌詞字幕或需要完全手工控制的情境。建立後同樣可使用匯出與燒錄功能。

## 三、語音辨識引擎設定（語音轉寫與文字稿對齊皆會用到）

### 方式 A：使用 OpenAI API（推薦給一般使用者）

1. 在「運作模式」選〔語音轉寫〕或〔文字稿對齊〕（「轉寫設定」在這兩個模式下都會顯示）。
2. 在「轉寫設定」勾選 **改用 OpenAI API**。
3. 於「API 金鑰」欄位填入你的 OpenAI API Key。
4. 選擇生成字幕即可，無須安裝任何額外程式。

### 方式 B：使用本地 Whisper（免費、可離線）

由於本程式為輕量版 exe，**並未內建 Whisper**。exe 是封閉環境，無法直接讀取你用 pip 安裝的套件，因此需採「外部 Python」方式串接：

#### 若你尚未安裝 Whisper

1. 安裝 [Python](https://www.python.org/downloads/)（3.9 以上版本），安裝時勾選 **Add Python to PATH**。
2. 開啟命令提示字元，執行：
   ```
   pip install openai-whisper
   ```
3. 確認 ffmpeg 已安裝（見第一節）。
4. 回到本程式「轉寫設定」的 **本地 Python** 欄位：
   - 留空：程式會自動偵測系統 PATH 上的 Python。
   - 或按「瀏覽...」指向該 Python 的 `python.exe`（通常位於
     `C:\Users\你的帳號\AppData\Local\Programs\Python\PythonXX\python.exe`）。
5. 之後選擇生成字幕，程式即會透過該 Python 執行 Whisper 轉錄。

#### 若你已經安裝過 Whisper

直接在「本地 Python」欄位按「瀏覽...」，指向「當初安裝 whisper 的那個 Python 的 `python.exe`」即可，程式會自動使用它。

> 查詢 python.exe 位置：開啟命令提示字元輸入 `python -c "import sys; print(sys.executable)"`，顯示的路徑即是。

#### 本地模型選擇

「本地模型」可選 `tiny` / `base` / `small` / `medium` / `large`，模型越大越準確但越慢。模型會於首次使用時自動下載。

#### 語言選擇

「語言」欄位除 `auto`、`zh`、`en` 等代碼外，另提供 **`zh-TW`**。Whisper 本身只認 `zh` 且預設常輸出簡體中文；選擇 `zh-TW` 時，程式會以 `zh` 辨識並加繁體提示詞偏導，再自動把結果轉換為台灣繁體中文。需要繁體字幕時請選 `zh-TW`。

## 四、智慧斷句設定

「斷句設定」區塊可即時調整，兩種模式皆適用：

| 設定項目 | 說明 | 調整範例 |
|----------|------|----------|
| 中文單行上限 | 中文字幕單行最大字數，超過會自動斷行 | 手機直向觀看字幕常顯太長時，調小到 14～16 字；橫向大螢幕可放寬到 20 字以上 |
| 英文單行上限 | 英文字幕單行最大字母數 | 同上邏輯，手機觀看建議 30～36 字母 |
| 最短秒數 | 每句字幕停留在畫面上的最短時間（過短會自動延長） | 觀眾反映字幕一閃即逝時調大（如 1.5 秒） |
| 最長秒數 | 每句字幕停留在畫面上的最長時間（過長會自動裁切） | 長句被硬切太短時可調大（如 6～8 秒），但避免整段影片只有幾句字幕 |
| 停頓秒數 | 音訊中靜音多久才算一次「停頓」，作為斷句與時間對齊的依據 | 講話語速快、停頓短的內容（如遊戲實況）可調小（0.3～0.5 秒）讓斷句更即時；語速慢、常有思考停頓的內容可調大避免斷句過於破碎 |

斷句演算法會優先依句末標點切句，其次依句中標點切子句，避免單一字幕文字過長霸佔畫面。不確定該調多少時，先用預設值生成一次字幕，看實際效果哪裡不順眼（太長／太短／停留太久／太快消失）再針對性調整，比一開始就大幅更動更容易抓到合適的數值。

## 五、字幕視覺調整

「字幕視覺調整」面板可即時設定：

- **位置**：水平 X、垂直 Y 滑桿，或使用「頂部／中部／底部」快捷鍵。
- **字型**：下拉選單內建常見中英文字型；旁邊的「...」按鈕可開啟字型選擇器，
  從系統字型中搜尋，或按「從字型檔匯入」載入自己的 `.ttf` / `.otf` 字型檔。
- **字型大小**、**文字顏色**、**邊框顏色**、**邊框寬度**。
- **重點字上色**（v1.6.0 起）：勾選後填入詞彙（逗號或空白分隔，如自己頻道的產品名、「免費」「限時」等），燒錄影片與匯出 ASS 時這些詞會自動換色強調（預設金黃、可選色）——CapCut 風格的重點標記，免逐句手動處理。SRT／VTT 純文字輸出不受影響。

  **範例：** 帶貨直播剪輯常見句子「這個現在**免費**送，數量**限時**搶購」，只要在重點字欄位填入 `免費, 限時`，之後每一句字幕只要出現這兩個詞就自動變色，不必逐句手動上色；詞彙用逗號或空白分開即可一次填多個，長詞（如「破盤價」）會優先於短詞比對，不會被短詞截斷。想要不同影片用不同顏色（例如促銷用紅色、重點用金黃），改變「重點字顏色」即可，設定會隨樣式一起記憶。

- **動態字幕**（v1.7.0 起）：逐字動畫字幕，於燒錄影片與 ASS 匯出時生效，兩種模式：
  - **逐字上色（卡拉OK）**：整句顯示在畫面上，講到哪個字、哪個字就換色（顏色沿用「重點字顏色」）——觀眾的視線跟著語音走
  - **單字彈出**：畫面上只顯示當前講到的字詞，並帶輕微放大彈出動畫——Shorts／Reels／TikTok 最常見的字幕版式，搭配大字級（例如 48 以上）與畫面中央位置效果最好
  - 需要逐字時間軸，因此**只在「語音轉寫」產生的字幕上生效**；手動字幕、文字稿對齊或編輯過的句子自動退回一般整句顯示，不會出錯
  - 審片助手輸出的直式短片若勾「燒錄字幕」，同樣套用此模式——單字彈出＋直式短片就是現成的 Shorts 成品

所有調整（含重點字上色，v1.6.1 起）都會即時反映在「即時字幕預覽」畫面上，改詞彙或顏色不必先燒錄就能看到效果（動態字幕的逐字動畫屬於影片時間軸效果，預覽維持整句顯示，實際效果以燒錄輸出為準）。

### 習慣設定（樣式組合）

「習慣設定」可儲存多組樣式組合（包含字幕樣式與斷句設定）：

- **另存新樣式**：將目前所有設定存成一組新樣式並命名。
- **更新目前樣式**：以目前設定覆寫選取中的樣式。
- **刪除**：移除選取的樣式。

- 習慣設定區最下面有一行狀態（v2.3.3 起）：目前畫面上的值跟選取的那一組一致時會寫「目前的值與「○○」一致」；改過字幕外觀或斷句設定、還沒存進去時，會寫出改了哪一部分，提醒你按〔更新目前樣式〕或〔另存新樣式〕。

## 七、生成與匯出

**建議直接走〔開始生成字幕〕→〔完成輸出（依輸出設定）〕**（見開頭「快速上手」），匯出、燒錄依設定自動完成。以下為需要逐句檢查、微調時的手動流程：

1. 選擇模式、匯入檔案（文字稿對齊另需貼上文字稿）。
2. 按「開始生成字幕」，狀態列會顯示進度。
3. 生成完成後，字幕清單會列出每一句字幕，點選任一句可在預覽畫面中檢視，雙擊可編輯。
4. **校對**：同一個錯字整集重複出現時（人名、產品名、同音字），按「**尋找取代**」（v1.7.0 起）一次修正——「找下一個」逐句檢視、「取代目前」逐句確認、「全部取代」一鍵修完並回報次數；對話框開著仍可操作清單。
   - **自動修正詞庫（v1.8.0 起）**：對話框下方按「**把目前取代存為規則**」，這個錯字之後**每次生成字幕都會自動修正**，不必每集重修。語音辨識對特定人名、產品名的錯法通常很固定，累積幾條規則後校對量會明顯下降；規則可隨時在清單中刪除，重存同一錯字則更新規則。
5. 按「匯出 SRT／VTT／ASS／TXT」選擇儲存位置輸出字幕檔，或按「燒錄字幕到影片」輸出硬字幕影片。

### 字幕翻譯：一鍵雙語字幕（v1.18.0 起）

YouTube 的自動字幕功能無法輸出雙語軌，超過三分之二的觀看時數卻來自創作者所在地區以外——生成字幕後，按字幕清單下方的「**翻譯字幕**」即可一鍵翻譯：

1. **選目標語言**：11 種語言可選（英/日/韓/繁中/簡中/西/法/德/印尼/越南/泰）。
2. **選模式**：「雙語（原文＋譯文上下行）」讓每句字幕顯示原文與譯文兩行；「僅保留譯文（取代原文）」直接用譯文取代原字幕（可重新生成復原，不影響原始素材）。
3. 按「開始翻譯」。**需要 OpenAI API 金鑰**——沿用「轉寫設定」裡已填的那一把，不必再另外申請，按用量計費。
4. 翻譯完成後自動套用到字幕清單，可再用「尋找取代」校對；雙語行匯出與燒錄時分兩行顯示。

**譯文由 AI 產生，建議翻譯後抽查幾句**，尤其是人名、專有名詞與語氣是否恰當。另外，逐字動態字幕（卡拉OK／彈出字模式）在翻譯後會自動退回整句顯示——翻譯後的文字與原本的逐字時間軸已經對不上，直接顯示整句字幕最穩妥。

### 匯入既有字幕檔（v1.19.0 起）

本工具原本只能「匯出」字幕，手上已經有的字幕檔——下載的 YouTube 自動字幕、其他工具產出的檔案、舊專案留下的字幕——完全進不了工具，只能開記事本手動改。現在可以按「**匯入字幕**」（v2.3.5 起在〔① 素材與剪輯〕的「既有字幕」卡片；之前在字幕清單下方），選取 .srt／.vtt 檔即可直接載入，接上編修、樣式、翻譯、燒錄整條既有管線。

**典型工作流程**：下載 YouTube 自動字幕 → 匯入本工具修正錯字（尋找取代）→ 翻譯成雙語字幕 → 燒錄成硬字幕影片（TikTok／Reels 等平台不支援外掛字幕檔，這是唯一選項）。

1. 按「**匯入字幕**」選擇 .srt 或 .vtt 檔；目前清單非空時會先確認是否取代。
2. 匯入成功後狀態列顯示「已匯入 N 句字幕（略過 M 段無法解析、編碼 X）」，〔② 字幕〕頁的字幕清單與預覽同步更新；要剪停頓或重複片段的話，在〔① 素材與剪輯〕同一頁接著按即可。
3. 之後即可比照一般生成結果操作：尋找取代校對、翻譯字幕、調整樣式、匯出其他格式或燒錄硬字幕。

**格式容錯細節**：
- **YouTube VTT 行內標記**：自動清除逐字時間戳 `<00:00:01.500>`、顏色／語者標籤 `<c>`、`<v Speaker>`，以及 `<i>`／`<b>`／`<u>`／`<font>` 等常見標記與 `{\an8}` 等 ASS 覆寫碼。
- **編碼自動偵測**：依序嘗試 UTF-8（含 BOM）／繁體 Big5 系列（cp950）／簡體（gb18030），Windows 上常見的非 UTF-8 字幕檔不會變亂碼。
- **略過壞區塊不中斷**：索引行可省略、時間軸容忍逗號或點分隔的毫秒、CRLF／CR 換行皆可解析；單一區塊格式有誤只略過該段並計入略過數量，不會讓整份檔案匯入失敗。

**CLI**：`python main.py --subs 影片.srt --burn 影片.mp4` 可跳過語音辨識，直接用既有字幕檔匯出其他格式並燒錄硬字幕（見下方命令列批次模式）。

### 字幕健檢：閱讀速度與行數（v1.20.0 起）

> **v1.50.0 起：本節描述的判斷邏輯全數保留，入口併入「健檢中心」**
> （見前面「健檢中心」一節）。字幕清單下方原本的「字幕健檢」按鈕只會切到
> 健檢中心，v2.3.5 起移除：直接點〔③ 健檢中心〕頁籤，勾「字幕健檢」即可。

字幕檔案審核最常見的退件原因就是「觀眾根本來不及讀完」——業界常用 CPS（每秒字元數）當量尺，Netflix 成人內容上限 20、BBC 建議 15 以下。本工具生成字幕時雖然有斷句規則限制單行字數，但翻譯（雙語內容變兩倍長，時間軸卻沒變）、匯入既有字幕檔（品質不明）、手動新增或編輯的字幕都可能產生從未檢查過的過快字幕。

在〔③ 健檢中心〕勾「**字幕健檢**」，掃描目前清單（不論字幕從何而來）並標出五類問題：

| 檢查項目 | 內容 | 預設門檻 |
|----------|------|----------|
| **閱讀速度過快** | 每秒字元數（CPS）超過門檻 | 17 字/秒 |
| **顯示時間過短** | 單句顯示秒數太短，來不及注意到 | 0.8 秒 |
| **行數過多** | 單句超過建議行數 | 2 行 |
| **單行過長** | 單行字元數超過建議寬度 | 21 字 |
| **字幕重疊**（v1.23.0 起） | 前後兩句時間軸重疊 | 有重疊即標記 |

- 門檻皆可在對話框調整並自動記憶（例如面向兒童或需要精讀的教學內容可調得更嚴格）。
- 按「**一鍵延長過快字幕**」：把 CPS 超標或顯示過短的句子，在**不與下一句重疊**的前提下自動延長顯示秒數（只調整時間軸，不改動文字內容）；下一句銜接太緊、沒有空檔可用時保留原樣，不會強行製造新的重疊，這時建議改為精簡文字內容。
- 按「**一鍵修復重疊**」（v1.23.0 起）：截短較早一句的結束時間消除重疊；起始時間相同或反序、單靠截短無法消除時，較早一句改保留極短長度、較晚一句整段順延並保留原本時長不變。**這是匯入既有字幕檔與手動編輯特別需要的檢查**——生成字幕（語音轉寫／文字稿對齊）內建正規化已保證不重疊，但匯入檔案品質不明、手動編輯也未曾檢查起訖時間是否與相鄰句子衝突，時間軸重疊常導致 YouTube 等平台匯入失敗或播放異常。
- CLI：`python main.py --subcheck 影片.mp4` 輸出「檔名_字幕健檢.txt」（含重疊檢查），可與一般轉錄／對齊模式或 `--subs` 併用（`--review` 等不產生字幕的模式無效果）；實際修復請於 GUI 操作。

#### 中文字幕標點規範（v1.47.0 起）

**逐字稿的標點跟字幕的標點不是同一回事。** Whisper 產出的是書面標點齊全的逐字稿，而中文字幕有一套相當一致的慣例：**句末不加句號與逗號**——斷行本身就已經表達了停頓，下一句本來就是另一張畫面；但**問號與驚嘆號要保留**，那兩個帶的是語氣。Netflix 的字幕風格指南講得最直接：句末標點只允許問號與驚嘆號。

本工具的斷句演算法又刻意**切在逗號上**，兩件事加起來的結果是：**幾乎每一句字幕都以一個沒有作用的逗號結尾**。實測四種常見影片類型的講稿共 27 句，**85% 的句子以標點結尾**。

字幕健檢對話框下方的「**中文標點規範**」提供三段強度（自動記憶）：

| 強度 | 做什麼 | 適合 |
|------|--------|------|
| **只拿掉行尾標點**（預設） | 只清掉行尾的「，。、；：」 | 絕大多數情況；改動最小、爭議最少 |
| **完整字幕慣例** | 再把**句中**的逗號、頓號改成全形空格 | 想要接近專業字幕組的排版 |
| **不套用** | 只看報告不改字 | 頻道風格就是要留標點 |

- **問號、驚嘆號、刪節號一律保留**，不受強度影響。
- **英文字幕完全不會被動到**。英文的逗號與句號是文法的一部分，`Hello, everyone.` 拿掉標點會變成錯的句子；本功能只處理中日韓字元佔一定比例以上的行（預設 0.15，實測中英夾雜的中文行最低 0.27、純英文行最高 0.06，門檻落在中間）。所以像「我用的是 Premiere Pro，」這種中英夾雜的行會正確處理，而「I use Premiere Pro, and it works fine.」原封不動。
- **整行只有標點時不會被清空**，避免吃掉一句字幕。
- 按「**一鍵套用標點規範**」就地套用到目前的字幕清單（只改文字，時間軸完全不動）。
- CLI：`python main.py --punctcheck 影片.mp4` 輸出「檔名_標點規範.txt」；加上 `--punctfix` 另存「檔名_標點規範.srt」。強度可於 `config.json` 的 `punctstyle` 調整（`mode`：`trim`／`subtitle`／`off`；`space`：句中逗頓要換成的空白；`cjk_ratio`：中文行判定門檻）。

#### 廣告友善度自查：上傳前先自己抓黃標（v1.29.0 起）

「黃標」（影片被標為不適合多數廣告主）通常是上傳後才被系統標記，申訴要等、重新審查也要等；社群流傳的自保作法是「先以不公開模式上傳、靜置 12~24 小時等系統掃描」，等於每支影片都要多花一天。本工具已經有完整逐字稿與時間軸，字幕健檢的報告因此**同時附上廣告友善度自查**，幾分鐘內就能先自己看過一遍。

- **重點是「高風險段落」而不是逐詞抓**：YouTube 的判定看的是短時間內的關鍵字叢集，不是單一詞——歷史頻道講一次「步槍」通常沒事，短時間內密集出現一整串相關詞才會被歸類。本功能因此用**時間窗加權叢集分析**（預設 30 秒窗、風險分數 3 分為門檻，皆可調）標出真正該優先處理的段落，零星單次提及不會誤報。
- **開頭數秒另外加強提醒**：依 YouTube 2025 年 7 月粗俗用語政策更新，開頭數秒的用詞對營利判定影響特別大，落在開頭區間（預設 7 秒，可調）的命中會單獨列出。
- **依頻道題材裁剪**：新聞、歷史、醫療、遊戲頻道本來就會提及部分詞彙，填入「**排除誤判詞**」之後就不再重複標記；也可用「**自訂補充詞**」加入自己頻道特有的風險詞。設定自動記憶。
- **只提醒、不改動內容**：同一個詞在教育、新聞、遊戲實況情境下的風險完全不同，自動消音反而可能破壞內容原意，因此本功能只負責報告與建議。
- **這不是官方清單**：YouTube 從未公布官方禁用詞列表，內建詞表是依「廣告客戶青睞內容規範」的主題分類整理的自查起點；實際判定另包含畫面、標題、縮圖與整體脈絡——**命中不代表一定被標記，未命中也不保證不會被標記**。
- CLI：`python main.py --adcheck 影片.mp4` 輸出「檔名_廣告友善度.txt」，可與一般轉錄／對齊模式或 `--subs` 併用。

#### 字幕與語音同步檢查／一鍵校正（v1.30.0 起）

匯入既有字幕檔（下載的字幕、其他工具產出的檔案、舊專案留下的檔案）最常見的翻車點就是**跟聲音對不上**。這分兩種成因、解法完全不同：

| 症狀 | 成因 | 解法 |
|------|------|------|
| **固定偏移**：整條字幕一致地早或晚 | 匯出設定不同、片頭被剪掉、平台處理延遲 | 整軌平移 |
| **逐漸漂移**：開頭對得上、越後面差越多 | **幀率不符**（23.976 fps 的字幕套到 25 fps 版本會漂移約 4.3%，90 分鐘影片到片尾差近 4 秒） | 依比例縮放時間軸，平移救不回來 |

字幕健檢視窗按「**檢查與語音同步**」，本工具會掃出素材的**實際語音區間**（不必你自己找錨點），計算字幕落在語音上的貼合度，並搜尋最佳的「縮放倍率 × 偏移秒數」線性校正——**一次同時涵蓋上面兩種情況**：

- 縮放倍率只試常見幀率比值（23.976／24／25／29.97／30 互換），因為漂移的成因就是幀率不符；這比盲目搜尋任意倍率更穩，也更不容易把本來就對齊的字幕改壞。
- 除了看全片平均貼合度，另外比較**頭尾三分之一的落差**——漂移會被對得很準的開頭稀釋掉平均值，只看平均會漏判。
- 按「**一鍵校正同步**」自動套用，**只調整時間軸，不改動或刪除任何文字內容**（逐字動態字幕的時間軸也會一併校正）。
- 只有在校正後明顯更好時才會建議套用；素材幾乎全程有聲（連續講話或整片配樂）時，語音區間提供不了對齊資訊，會明確告訴你「無法可靠判定」而不是硬給一個看似精確的錯誤數字。
- CLI：`python main.py --subs 舊字幕.srt --synccheck 影片.mp4` 輸出「檔名_同步檢查.txt」；加上 `--syncfix` 會直接另存校正後的「檔名_同步校正.srt」（原始字幕檔不受影響）。

### 全片停頓自動跳剪（v1.21.0 起）

創作者社群公認「剪掉停頓」是初剪最花時間、最想自動化的一步——本工具已有的「一鍵去頭尾」只處理開頭結尾廢秒，中段每一句換氣、思考停頓仍要手剪。

字幕清單下方按「**自動跳剪停頓**」：依目前字幕的時間軸找出句與句之間過長的停頓，一次剪掉整支影片的冷場——**字幕時間軸同步重新對齊**，剪完不必再手動調整字幕。

- 先按「**預覽跳剪點**」（純分析目前字幕，免呼叫 ffmpeg，瞬間看到偵測到幾處停頓、預估能省下多少秒數），確認合理後再按「**輸出跳剪版**」實際裁切
- 門檻皆可調並自動記憶：**最短停頓秒數**（達此長度才視為可跳剪的冷場，預設 1.2 秒）、**緩衝秒數**（剪點兩側各保留的秒數，避免斷得突兀，預設 0.15 秒）、**安全上限**（跳剪總長度超過影片長度的此比例時自動中止，防止門檻設太低誤剪，預設 60%）
- 輸出 `素材_跳剪.mp4`＋時間軸已對齊的字幕檔（同資料夾）
- CLI：`python main.py --jumpcut 影片.mp4`，可與一般轉錄／對齊模式或 `--subs` 併用；`--burn` 燒錄的仍是原始（未跳剪）影片，兩者暫不會自動串接

### 重複片段偵測與剪除（v1.22.0 起）

同一句話講了好幾次、要手動翻逐字稿找出前面講壞掉的版本剪掉——這是初剪另一個吃時間的步驟。

字幕清單下方按「**重複片段偵測**」：找出同一時間窗內文字高度相似的句子（同一句話的前後幾次嘗試），只保留最後一次。**這裡動的是實際講話內容，假陽性風險比純靜音的跳剪高**（例如刻意重複的口號、報數測試麥克風），因此設計為先列出候選逐項勾選確認，才真正剪：

- 「**偵測重複片段**」（純分析目前字幕，免呼叫 ffmpeg）列出候選清單，預設全選，可自行取消勾選誤判項目，再按「**剪掉勾選的重複片段**」實際裁切
- 門檻皆可調並自動記憶：**相似度門檻**（兩句文字達此相似度才視為同句重講，預設 72%）、**比對時間窗**（只比對此秒數內的句子，間隔太遠不算重錄，預設 25 秒）、**剪點外擴秒數**（連同前後的吸氣停頓一起剪掉，預設 0.2 秒）
- 剪完影片同步把字幕時間軸重新對齊、被剪掉的句子從清單移除；輸出 `素材_去重複.mp4`＋對齊後的字幕檔
- CLI：`python main.py --retakes 影片.mp4` 只輸出候選清單「檔名_重複片段.txt」（不自動剪）；搭配 `--retakes-cut` 才會實際剪掉全部候選（命令列無法逐項確認，建議先用 `--retakes` 看過候選清單再決定）

## 九、常見問題

**Q：點「開始生成字幕」後出現「找不到 ffmpeg」？**
A：請依第一節安裝 ffmpeg 並加入系統 PATH。

**Q：本地轉錄出現「找不到可用的本地 Whisper」？**
A：請依第三節方式 B 安裝 Whisper，並在「本地 Python」欄位指向正確的 python.exe，或改用 OpenAI API 模式。

**Q：視窗內容顯示不下？**
A：視窗可自由縮放，內容超出時可使用右側／底部捲軸，或用滑鼠滾輪捲動。
字幕生成完成後（含〔批次一鍵完成〕批次生成），若清單原本不在視窗可視範圍
內，會自動捲動到字幕清單處，不必自己往下找（v1.49.0 起）。

**Q：字幕斷句太長或太短？**
A：於「斷句設定」調整單行字數上限與秒數限制後重新生成。

**Q：〔完成輸出〕／〔批次一鍵完成〕的檔案輸出到哪裡？**
A：預設輸出到來源影片所在的資料夾，檔名沿用來源檔名（如 `影片.srt`、`影片_subtitled.mp4`）。想集中輸出到固定資料夾，可在「自動化輸出」的「輸出資料夾」指定。同名檔不會被覆蓋，會自動加上 `(1)` 流水號。

**Q：把檔案拖到 exe 圖示上沒有反應？**
A：拖曳執行採用「自動化輸出」記憶的設定，請先開啟程式在「自動化輸出」勾選至少一種匯出格式（或燒錄），關閉程式後再拖曳。處理需要時間（轉錄與燒錄），完成後才會跳出結果視窗。

**Q：審片助手的「精彩片段」是怎麼判定的？標太多／太少怎麼辦？**
A：綜合四種訊號評分——說話音量能量、語速、情緒詞（哇、太扯、wow…）與驚嘆句，達門檻即標記。標太少請到「偵測設定」把**精彩敏感度**調高（如 1.5），標太多就調低（如 0.7）；也可在**自訂情緒詞**加入自己頻道常用的口號與梗詞，讓判定更貼合內容。設定會自動記憶。

**Q：同一支影片轉錄過了，換個功能又要重新等辨識？**
A：v1.4.0 起內建轉錄快取：同一檔案且轉寫設定相同時自動重用先前結果（例如審片分析完再一鍵上字幕，第二次瞬間完成）。快取存於程式資料夾的 `transcribe_cache/`，自動限量清理；不需要時可在「轉寫設定」取消勾選「重用轉錄快取」。

**Q：輸出的直式短片人物不在畫面中間？**
A：「裁切」版式預設焦點 0.5（畫面正中）。人物偏左調小（如 0.3）、偏右調大（如 0.7）後重新輸出；或改用「模糊背景」版式保留完整畫面。

**Q：響度正規化該用什麼目標值？**
A：一般影片用預設 **-14 LUFS**（YouTube 標準）即可。想在正規化後仍略高於平台基準，可用 -13～-11；Podcast 類口說內容常用 -16。設定會記憶，不需每次調整。

**Q：轉錄結果在同一時間點出現多句重複字幕？**
A：這是 Whisper 遇到靜音或背景音樂時的已知現象（幻覺迴圈），v1.4.0 已加入三層自動去重防護。若仍遇到，可回報 issue 並附上來源音訊特徵（如長靜音、純音樂段）。

**Q：動態字幕（卡拉OK／單字彈出）選了卻沒有效果？**
A：動態字幕需要逐字時間軸，只在「語音轉寫」產生的字幕上生效；手動字幕、文字稿對齊或編輯過文字的句子會自動退回一般整句顯示。另外效果只出現在**燒錄影片與 ASS 匯出**——「即時字幕預覽」與 SRT／VTT 輸出維持整句。若整支影片都沒有效果，請確認字幕是本次以「語音轉寫」生成的（重新按「開始生成字幕」即可）。

**Q：尋找取代會改到時間軸嗎？改錯了怎麼辦？**
A：尋找取代只改文字，時間軸完全不動。「全部取代」前可先用「找下一個」逐句檢視命中的句子；若取代錯了，把「尋找」與「取代為」兩欄對調再全部取代一次即可還原。

**Q：每集都要重修同樣的錯字（人名、產品名），有辦法記住嗎？**
A：有（v1.8.0 起）。在「尋找取代」填好錯字與正確字後，按下方「**把目前取代存為規則**」——之後每次生成字幕（含〔完成輸出〕與 CLI 批次）都會自動套用，不必再手動修。規則清單就在對話框下方，可隨時刪除或重存更新。

**Q：背景音樂較大聲的素材，精彩片段是不是標得怪怪的？**
A：v1.8.0 起音量分析預設聚焦人聲頻帶（150～4000 Hz），配樂鼓點不再干擾精彩判定，直接重新分析即可。若素材本身以音樂為主體（樂器演奏、DJ），到「偵測設定」關閉「音量聚焦人聲頻帶」。

**Q：勾了「剪除口頭禪字」，粗剪聽起來會不會很跳？**
A：有三層保護：太短的口頭禪（<0.12 秒）不剪、剪點向內縮小緩衝不切到相鄰字、剪除後過短的殘片自動捨棄，多數口播素材效果自然。若素材語速很快、逐字跳剪頓挫感明顯，取消勾選改回整段取捨即可；也可改用 EDL 進剪輯軟體，剪點相同但可逐一微調。

**Q：發佈包的建議標題／標籤是怎麼來的？可靠嗎？**
A：標題取自「精彩分數最高的段落文字」——觀眾反應最大的內容通常就是影片賣點；標籤取自素材中實際講到的高頻詞（你的自訂情緒詞優先、中文高頻詞組、英文高頻詞）。它們是「初稿與靈感」而非成品：標題建議挑一個再潤飾、標籤上傳前自行增刪。想要更多候選，調大 `config.json` 裡 `publish` 的數量設定。

**Q：配樂助手輸出後，音樂閃避的效果聽起來還是不太對？**
A：先確認調的是哪個方向的問題——講話時**音樂還是蓋過人聲**：調高「閃避強度」；閃避**忽大忽小很突兀**（例如講話中間有短暫停頓就跳回原音量）：調低「閃避強度」或調高「閃避靈敏度」數值讓觸發沒那麼敏感；整體**音樂太大聲或太小聲**（跟閃避無關）：直接調「音樂音量」。三個旋鈕互相獨立，一次只調一個比較容易聽出差異。

**Q：審片助手輸出的 EDL 怎麼用？**
A：在 Premiere Pro 選「檔案 → 讀入」、DaVinci Resolve 選「File → Import → Timeline」載入 `.edl`，再連結原始素材，時間軸就是保留段落的順剪，可直接開始精剪。

**Q：粗剪影片／精彩合輯輸出後聲音或畫面不同步？**
A：粗剪採重新編碼（libx264＋AAC）確保剪點精準，一般不會不同步；若來源影片編碼特殊，建議改用 EDL 進剪輯軟體處理。
