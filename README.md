# SRT 自動字幕生成與編輯工具

一套 Windows 桌面應用程式，可將影片／音訊轉錄為 SRT 字幕，或匯入現成文字稿自動對齊時間軸。內建智慧斷句、即時預覽與字幕樣式調整功能，並提供「一鍵完成」與批次處理，把生成、匯出、燒錄濃縮成一個步驟；「審片助手」則以文字審片自動標記精彩片段、冷場與重複拍攝，快速從素材挑出可用片段並輸出粗剪影片或 EDL；「配樂助手」可一鍵幫影片配上背景音樂並自動閃避人聲，免除手動調音量的麻煩；「上片前健檢」一鍵檢查爆音、音量、底噪與影片畫質（位元率、解析度對照 YouTube 建議），並偵測頭尾廢秒一鍵修剪；「封面候選」自動從精彩片段挑出清晰畫面當縮圖素材；「品牌套版」設定一次片頭片尾與浮水印，之後每支影片一鍵套用，不必再重複手動接片頭片尾、調浮水印位置。

## 快速上手：一鍵完成（v1.3.0 起）

日常上字幕只需三步，全程不再跳出任何存檔對話框：

1. **選檔**：按「瀏覽...」選擇影片（可按住 Ctrl / Shift 一次選多個檔案批次處理）。
2. **勾選輸出**：在「自動化輸出」勾選要匯出的格式（SRT／VTT／ASS／TXT），需要硬字幕影片就勾「燒錄硬字幕影片」。這些勾選會被記憶，之後不必再設定。
3. **按「一鍵完成」**：程式自動完成「生成字幕 → 匯出檔案 → 燒錄影片」整條流程。

輸出規則：

- 輸出檔自動以來源檔名命名：`影片.mp4` → `影片.srt`、`影片_subtitled.mp4`。
- 預設輸出到來源檔所在資料夾；也可在「自動化輸出」指定固定的輸出資料夾。
- 同名檔已存在時自動改名為 `影片 (1).srt`，不會覆蓋舊檔。
- 批次處理時逐檔顯示進度（`[2/5] 影片B.mp4：...`），單一檔案失敗不會中斷整批，結束後會列出成功與失敗清單。
- 完成後最後一個檔案的字幕會載入清單，可直接檢視、微調後用下方按鈕重新匯出。

**批次跑「模式二：文字稿對齊」**：把每部影片的文字稿存成旁邊同名的 `.txt`（如 `演講.mp4` 配 `演講.txt`），程式會自動帶入，不必逐一貼上。

### 最快的用法：把檔案拖到 exe 圖示上

在檔案總管把一個或多個影片**直接拖曳到 `SRT-Subtitle-Generator.exe` 圖示上**，程式會依記憶的自動化設定靜默跑完整條流程，結束後以視窗回報每個檔案的輸出結果——連程式視窗都不用開。

### 命令列批次模式（進階）

不開視窗也能跑同一條自動流程，設定沿用 `config.json`（在 GUI 調好一次即可）：

```
python main.py 影片1.mp4 影片2.mp4          # 依記憶的自動化設定批次處理
python main.py --burn 影片.mp4              # 本次強制燒錄硬字幕
python main.py --formats srt,ass 影片.mp4   # 本次改匯出 SRT 與 ASS
python main.py --mode align 演講.mp4        # 文字稿對齊（文字稿放在同名 .txt）
python main.py --output-dir D:\out 影片.mp4 # 本次輸出到指定資料夾
python main.py --audiocheck 影片.mp4        # 上片前音訊健檢（免轉錄）
python main.py --videocheck 影片.mp4        # 影片畫質健檢＋頭尾廢秒（免轉錄）
python main.py --thumbnails 影片.mp4        # 封面候選圖（免轉錄，均勻取樣）
python main.py --subs 影片.srt --burn 影片.mp4   # 既有字幕直接燒錄（免轉錄，v1.19 起）
python main.py --subcheck 影片.mp4          # 字幕健檢：CPS／行數，可與其他模式併用（v1.20 起）
```

命令列旗標僅影響本次執行，不會改寫記憶的設定。適合搭配排程或一次處理整批檔案。

## 審片助手：拍完快速找可用片段（v1.3.0 起）

拍完素材後來回拉時間軸找片段最耗時。審片助手改用**文字審片**——讀逐字稿遠比看影片快，且系統會先幫你標好可剪的內容：

1. 選好素材後按工具列的「**審片助手（找片段）**」，再按「開始分析」。
2. 系統轉錄素材、分析音量能量，切成講話段落並自動標記四類內容：
   - **精彩片段**（綠色）：綜合音量能量、語速、情緒詞（哇、太扯、wow…）與驚嘆句評分，達標即標記
   - **冷場**（灰色）：長時間無人聲（門檻可調，預設 2 秒）→ 預設捨棄
   - **重複拍攝**（琥珀色）：同一句話重講多次（吃螺絲重來），自動只保留最後一次 → 前面幾次預設捨棄
   - **口頭禪多**（琥珀色）：「呃、嗯、欸」等填充詞密集的段落 → 標記供複查（仍保留）
3. **一眼總覽**：視窗上方的**彩色時間軸**把整條素材畫成色帶——綠色是精彩、琥珀色待審視、灰色冷場、藍色一般內容，捨棄段以網點淡化；點任一色塊直接跳到對應段落。清單列也依同色系上底色，並顯示保留／精彩／冷場時長統計。
4. 掃一遍清單微調：雙擊或空白鍵切換保留／捨棄；「只看精彩」「只看待審視」篩選快速聚焦；關鍵字搜尋跳到講到某主題的段落。
5. 一鍵輸出（皆自動命名、不跳對話框）：

### 偵測設定：依自己的頻道風格調整（v1.4.0 起）

審片視窗的「偵測設定」區可調整所有判定參數，自動記憶、下次分析生效：

| 參數 | 預設值 | 可調範圍 | 調高會怎樣 | 調低會怎樣 |
|------|--------|----------|------------|------------|
| **精彩敏感度** | 1.0 倍 | 0.2～3.0 | 更多段落被標成精彩（綠色變多） | 判定更嚴格，只有反應最大的段落才標精彩 |
| **自訂情緒詞** | （空） | 自由輸入 | 加入的詞出現時更容易被判定精彩 | — |
| **口頭禪字表** | 呃嗯欸蛤齁 | 自由輸入 | 更多字被算進口頭禪密度 | 少算一些字，避免正常用字被誤判 |
| **冷場門檻** | 2 秒 | 0.5～10 | 更久的安靜才算冷場（保留較多安靜片段） | 較短的安靜就標記冷場，剪得更緊湊 |
| **段落切分停頓** | 1 秒 | 0.4～5 | 段落被切得更細（停頓稍長就分段） | 段落較長，只有明顯停頓才分段 |
| **重複判定相似度** | 0.72 | 0.5～0.95 | 判定更嚴格，只有幾乎一字不差才算重複拍攝 | 較寬鬆，措辭略有出入也會歸為同一次重講 |
| **口頭禪密度門檻** | 0.08 | 0.02～0.5 | 口頭禪要非常密集才標記「口頭禪多」 | 稍微多一點口頭禪就會被標記供複查 |
| **章節最短長度** | 60 秒 | 10～600 | YouTube 章節切得更粗（章節數變少） | 章節切得更細（章節數變多） |
| **精彩訊號權重**（v1.7.0 起） | 各 1.0 | 0～3 | 該訊號對精彩判定的影響變大 | 影響變小；調到 0 完全停用該訊號 |
| **音量聚焦人聲頻帶**（v1.8.0 起） | 開 | 開／關 | —（預設即開） | 關閉後音量分析涵蓋全頻帶；素材以音樂為主體（樂器演奏、DJ）時關閉 |

**音量聚焦人聲頻帶**：精彩偵測的音量訊號預設只看 150～4000 Hz 的人聲頻帶，背景配樂的低頻鼓點或高頻效果音不會再把普通段落「頂」成精彩——這是各家剪輯工具在背景音樂下準度下降的通病。一般拍攝素材維持預設開啟即可。

**精彩訊號權重**是四個獨立的旋鈕（音量、語速、情緒詞、驚嘆句），與「精彩敏感度」的差別：敏感度是整體門檻的高低，權重則決定**由哪些訊號來判定**。例如：

- 教學型影片語調平穩、很少驚呼 → 情緒詞 0.5、驚嘆句 0.5、音量 1.5：讓「講到重點自然提高音量」成為主要依據
- 遊戲實況激動時刻靠喊出來 → 音量 2.0、語速 1.5：抓住尖叫與連珠炮反應
- 想純靠內容文字判定（如錄音環境音量不穩） → 音量 0：完全忽略音量訊號

拿不準怎麼調時，建議的操作順序：**先用預設值跑一次分析 → 看彩色時間軸的結果 → 只調一個最不滿意的參數 → 重新分析比較差異**，而不是一次改動多個參數，比較容易看出哪個設定造成了影響。

#### 情境範例：三種常見素材類型的起始設定

以下是三種常見頻道／素材類型可以直接套用的起始值（仍可再依實際結果微調）：

| 情境 | 精彩敏感度 | 冷場門檻 | 重複判定相似度 | 說明 |
|------|-----------|----------|----------------|------|
| **Vlog／生活紀錄**（講話反應平緩，很少大喊大叫） | 1.3～1.5 | 2～3 秒 | 0.72（預設） | 語調變化小，敏感度調高才抓得到「相對」精彩的段落 |
| **遊戲實況／開箱剪輯**（情緒起伏大、常有驚呼） | 0.8～1.0（預設） | 1.5 秒 | 0.65（放寬） | 反應本來就多，用預設或略降即可；玩家常常重講同句台詞，相似度放寬更容易抓到重複 |
| **教學／知識型影片**（語速平穩、內容重於情緒） | 1.0（預設） | 3～4 秒（拉長） | 0.8（收緊，避免正常重述被誤判） | 錄影中常有思考停頓，冷場門檻拉長避免正常換氣被剪掉；教學常會刻意重複重點，相似度收緊避免誤刪 |

CLI 批次審片（`--review`）沿用同一組記憶的參數。

### Shorts 直式短片輸出（v1.5.0 起）

橫式素材重剪成 Shorts／Reels／TikTok 最花時間。審片助手輸出區的「**直式短片**」列可把任意段落一鍵轉成 9:16（1080x1920）直式影片：

1. 在段落清單**選取要輸出的段落**（Ctrl／Shift 可多選）；不選取則自動輸出所有**精彩片段**。
2. 選版式：
   - **裁切**：以「焦點」滑調（0 最左、0.5 置中、1 最右）決定取景位置，適合人物固定在畫面某側
   - **模糊背景**：完整畫面置中、上下以放大模糊的原畫面填滿，畫面資訊不損失
3. 可勾「**燒錄字幕**」（沿用你的字幕視覺樣式，時間軸自動平移）與「**響度正規化**」。
4. 按「輸出直式短片」，每段各輸出一支 `素材_短片01.mp4`，逐支顯示進度。

版式、焦點等設定會自動記憶。

**「焦點」怎麼調（範例）：** 先用 0.5（置中）輸出一支試看——人物若被裁到左邊畫面外，調小到 0.2～0.3；被裁到右邊畫面外，調大到 0.7～0.8。單人固定坐在鏡頭前的講話素材通常 0.5 就夠用；若人物在畫面中會左右走動，改用「模糊背景」版式較保險，不必為了裁切焦點反覆試錯。

### 響度正規化：告別影片太小聲（v1.5.0 起）

YouTube 會把超過 -14 LUFS 的音訊自動調小，但**太小聲的不會被調大**——錄音偏小聲的影片上傳後會一直小聲。解法：

- 在「自動化輸出」勾選「**燒錄時響度正規化**」，目標值預設 **-14 LUFS**（YouTube 標準，可調 -30～-8）。
- 之後「一鍵完成」與「燒錄字幕到影片」輸出的影片都會先量測實際響度、再線性校正到目標值（兩階段處理，比單次動態調整更精準、音質更好）。
- 直式短片輸出也有獨立的「響度正規化」勾選。
- CLI：`--loudnorm`／`--no-loudnorm` 可覆寫本次設定。

**目標值怎麼選（範例）：**

| 目標值 | 適合情境 |
|--------|----------|
| **-14 LUFS**（預設） | 一般 YouTube 影片，不確定要選什麼就用這個 |
| **-11～-13 LUFS** | 音樂／節奏感強的內容，想要比平台基準略響亮一點 |
| **-16 LUFS** | Podcast、純口說訪談，避免長時間收聽顯得刺耳 |
| **-19～-23 LUFS** | 供電視或需符合廣播響度規範的交付素材 |

不確定自己影片目前多大聲也沒關係——這個功能會自動先量測，你只需要決定「想要多大聲」這個目標值即可。

| 輸出 | 用途 |
|------|------|
| **粗剪影片（自動跳剪）** | ffmpeg 把保留段落串成一支影片，直接看粗剪效果 |
| **精彩合輯** | 只串接精彩片段——短影音（Shorts）、預告、亮點回顧素材 |
| **HTML 審片報告** | 單一檔案含彩色時間軸＋統計＋段落表，瀏覽器直接開，可傳給剪輯師 |
| **EDL（CMX3600）** | 匯入 Premiere Pro / DaVinci Resolve，時間軸即為保留段落，接著精剪 |
| **審片標記字幕（SRT）** | 與素材一起載入剪輯軟體，拉時間軸即見【精彩】【冷場】標記 |
| **CSV 片段清單** | Excel 檢視、備查、與剪輯師交接 |
| **YouTube 章節** | 智慧合併成合理粒度（見下），複製即貼影片說明欄 |
| **發佈包（v1.10.0 起）** | 建議標題候選＋描述草稿＋標籤清單，上傳時直接取用（見下） |
| **封面候選圖（v1.11.0 起）** | 從精彩片段自動挑清晰畫面輸出 PNG，縮圖素材免拖時間軸截圖（見下） |

**口頭禪自動剪除（v1.10.0 起）**：輸出區勾選「**剪除口頭禪字**」後，粗剪影片、精彩合輯與 EDL 會把保留段落裡的「呃、嗯、欸」等口頭禪**字詞本身**從時間軸剪掉（Descript 式 filler-word removal）——之前只能整段標記供複查，現在直接逐字剪除。內建防抖動保護：太短的口頭禪（<0.12 秒）不剪、剪點向內縮不切到相鄰字、剪除後過短的殘片自動捨棄；字表沿用「偵測設定」的口頭禪自訂字表。**建議先輸出一次粗剪聽聽效果**——講話節奏快的素材逐字跳剪可能略有頓挫感，不滿意取消勾選即可。

**一鍵發佈包（v1.10.0 起）**：按「**匯出發佈包**」輸出 `素材_發佈包.txt`——調研顯示多數創作者花大量時間剪片，標題、描述、標籤卻隨便帶過，導致點擊率與搜尋排名不佳。發佈包內含：
- **建議標題候選**（預設 3 個，v1.15.0 起按有效標題型態各出一手）：**精華句**（精彩分數最高段落，剝掉「然後、就是」等句首贅詞、以完整子句湊到長度上限，不再攔腰截斷）、**疑問句**（素材中實際講出的疑問，好奇缺口式）、**數字句**（含具體數字的句子）、**關鍵字冠頭**（【關鍵字】＋精華子句）——挑一個直接用或自行組合
- **描述草稿**：開場鉤子＋建議章節＋hashtag 行，複製後自行潤飾
- **建議標籤**（預設 15 個）：素材中實際講到的高頻詞——你的自訂情緒詞（頻道口號、產品名）優先、中文高頻詞組、英文高頻詞，上傳時自行增刪

候選數量與長度可在 `config.json` 的 `publish` 區調整（標題候選 2~6、標題長度 20~60、標籤數 5~30）；CLI 批次審片也會逐檔附上發佈包。

**封面候選擷取（v1.11.0 起）**：選封面得在播放器來回拖時間軸，肉眼找一格「清晰、有內容」的畫面截圖——現在按「**擷取封面候選圖**」即自動完成：從**精彩分數最高的段落**取樣畫面，以邊緣能量評分（動態模糊、黑畫面都會得低分）挑出最清晰的格，輸出 `素材_封面01.png`…（1280 寬，YouTube 封面標準，依清晰度排序）。可調參數（自動記憶）：
- **張數**（2~12，預設 6）與**最小間隔**（預設 8 秒）：間隔避免候選全擠在同一幕
- **優先取精彩段落**：取消勾選改為所有保留段落一視同仁；完全沒分析過的素材則整片均勻取樣

拿候選圖進 Canva 等工具加大字標題就是成品縮圖。CLI：`--thumbnails` 單獨使用（免轉錄、均勻取樣）或與 `--review` 併用（優先精彩段落）。

**mid-roll 廣告插入點建議（v1.13.0 起）**：YouTube 允許 8 分鐘以上的影片放 mid-roll 廣告，且官方指出**放在自然停頓、話題轉換處**的廣告點觀眾留存較高、也較容易被實際投放（插在句子中間的常被系統跳過）——但手動找停頓得再拉一次時間軸。審片助手輸出區的「**複製廣告插入點**」直接從分析結果挑點：
- 只挑講話段落之間**夠長的自然停頓**（預設 ≥1.2 秒），停頓越久（通常是話題轉換）越優先
- **最小間隔**（預設 4 分鐘）與**數量上限**（預設 6 個）可調並記憶；自動避開影片開頭 2 分鐘與結尾 1 分鐘
- 複製結果含時間戳、停頓秒數與**前後句摘要**，不用開影片就能確認每個點在講什麼之間；發佈包也會自動附上
- 時間以目前素材時間軸為準：未剪輯直接上傳可直接用；若上傳的是粗剪版，請以粗剪檔重新分析後再取點

**YouTube 章節智慧合併（v1.6.0 起）**：章節不會一段一章——只在大停頓（剪掉的冷場處）且目前章節已達「**章節最短長度**」（偵測設定可調，預設 60 秒）時才切新章，首章固定 0:00。覺得章節太細調大、太粗調小。

**批次審片（進階）**：`python main.py --review 素材1.mp4 素材2.mp4` 可整批分析、逐檔輸出審片清單 CSV 與 HTML 報告——睡前掛整天拍的素材，隔天直接看報告挑片段。

**多檔審片彙總（v1.7.0 起）**：批次審片兩支以上素材時，自動另輸出「**審片彙總.html**」與「**審片彙總_精彩TopN.csv**」——整批素材的精彩片段**跨檔**依分數排序，並附各素材統計對照表（總長、保留、精彩段數、冷場、口頭禪）。一天拍 20 支素材，隔天打開彙總頁就知道「這批裡最值得用的前 10 段」在哪支的第幾分鐘，不必逐檔比較。Top N 段數可在 `config.json` 的 `review.batch_top_n` 調整（3～50，預設 10）。

## 配樂助手：背景音樂自動閃避（v1.9.0 起）

幫影片配上背景音樂時，音樂蓋過講話聲是最常見的困擾——手動逐段拉關鍵影格調音量非常花時間（Premiere、Filmora、DaVinci Resolve 2026 年都已內建自動閃避功能）。工具列的「**配樂助手（自動閃避）**」提供同等效果，不必離開本程式：

1. 按工具列「**配樂助手（自動閃避）**」，分別選擇**影片**與**背景音樂**檔（若已選取檔案會自動帶入為影片）。
2. 調整三個強度旋鈕（自動記憶）：

| 旋鈕 | 範圍 | 預設 | 說明 |
|------|------|------|------|
| **音樂音量** | 0.05～1.0 | 0.35 | 混音前的音樂基礎音量——沒有人聲時音樂大概多大聲 |
| **閃避強度** | 1～20 | 8 | 講話時音樂被壓低的程度，數值越高，講話時音樂壓得越小聲 |
| **自動適應人聲音量** | 開／關 | 開 | v1.15.0 起：先量測影片的人聲響度，再自動計算靈敏度——人聲偏小聲（還沒做響度正規化）的素材也能正確觸發閃避，建議保持開啟 |
| **閃避靈敏度** | 0.01～0.5 | 0.06 | 「自動適應」關閉時才使用：數值越低，越輕的講話聲就會觸發閃避；環境音較吵的素材可調高避免誤觸發 |

3. 按「**輸出混音影片**」，程式自動偵測人聲並即時調整音樂音量，輸出 `影片_配樂.mp4`（同名自動加流水號，不覆蓋舊檔）。

背景音樂比影片短時會自動循環播放，輸出長度自動裁到與影片一致；影像串流原樣複製，只有音軌重新混音，**畫質完全不受影響**。

**怎麼調整最合適：** 先用預設值（自動適應開啟）跑一次，實際聽效果——音樂閃避後仍蓋過人聲，調高「閃避強度」；閃避太明顯、忽大忽小很突兀，調低「閃避強度」；閃避完全沒觸發或觸發過頭且已關閉自動適應，才需要手動調「閃避靈敏度」；覺得平時音樂太小聲或太大聲，直接調整「音樂音量」。

## 音訊健檢：上片前檢查聲音（v1.11.0 起）

「畫面差觀眾會忍，聲音差觀眾直接關掉」——爆音（clipping）、整體音量太小、底噪過高、麥克風只錄到單邊聲道，都是**上傳後才被留言提醒**的常見悲劇，而且事後幾乎救不回來。工具列的「**音訊健檢（上片前）**」一鍵掃描音軌（不改動原始檔），以檢查表回報四項檢查與具體修法：

| 檢查項目 | 檢查內容 | 常見修法 |
|----------|----------|----------|
| **整體響度** | 是否低於「太小聲門檻」（預設 -19 LUFS）或高於 YouTube 標準 | 輸出時勾「響度正規化」自動修正 |
| **爆音檢查** | 峰值是否貼頂、波形是否削平（真的爆掉） | 已爆音幾乎無法修復；重錄時增益調低、峰值留 -6 dB 餘裕 |
| **底噪檢查** | 底噪是否高於門檻（預設 -50 dB），安靜段落會聽到嘶聲 | 剪輯軟體降噪，或錄音時關風扇冷氣、麥克風靠近嘴巴 |
| **聲道平衡** | 左右聲道電平是否嚴重不均、甚至單邊無聲 | 剪輯軟體把音軌改單聲道或複製有聲聲道 |

- 四項門檻皆可在對話框調整並自動記憶（不同錄音環境可放寬或收緊）。
- 報告可一鍵複製或另存 `素材_音訊健檢.txt`。
- CLI：`python main.py --audiocheck 影片.mp4` 免開視窗批次健檢（免轉錄，速度快）；可與 `--review` 併用在審片時一起檢查。
- **建議把健檢排進上片前流程**：拍完先健檢，有紅字（✘）先處理再剪，比剪完才發現整批素材爆音省得多。

### 影片畫質健檢與一鍵去頭尾（v1.17.0 起）

同一個健檢視窗現在**連畫質一起檢查**（純音訊檔自動略過畫質段落）：

- **位元率**：對照 YouTube 官方建議上傳位元率（依解析度與更新率，如 1080p30 建議 8 Mbps、4K 35 Mbps）——位元率不足的影片上傳後會被 YouTube 重壓成一片糊，這是「上傳後才發現畫質變爛」最常見的原因；寬嚴倍率可調（預設 1.0×）
- **解析度／畫面更新率／編碼**：未達 720p、非標準更新率（常見於手機或螢幕錄影的可變更新率來源，可能造成影音不同步）、非主流編碼都會提醒
- **頭尾廢秒偵測**：掃描開頭／結尾的無聲與黑畫面（開機、清喉嚨的廢秒）——開頭空白是留存率殺手；偵測結果自動帶入「**一鍵去頭尾**」的修剪秒數，可微調後按「輸出修剪版」輸出 `素材_修剪.mp4`（重新編碼確保剪點精準、原始檔不受影響）
- CLI：`python main.py --videocheck 影片.mp4` 輸出 `素材_影片健檢.txt`，可與 `--audiocheck` 併用

### 音訊一鍵修復（v1.13.0 起）

健檢發現底噪偏高或太小聲，不必再把整支影片上傳到線上工具處理——健檢視窗下方的「**音訊修復**」直接輸出修復版（`素材_修復.mp4`，畫面原樣複製、只處理音軌，純音訊檔輸出 `.m4a`）：

| 修復項目 | 原理 | 適用情境 |
|----------|------|----------|
| **降噪**（強度 6~40 dB，預設 12） | FFT 頻譜降噪（afftdn） | 冷氣聲、電流聲、嘶聲等穩態底噪；強度過高人聲會發悶，建議先用預設值試聽 |
| **去低頻隆隆**（40~200 Hz，預設 80） | 高通濾波 | 桌面震動、風切、空調低頻；人聲基頻在 85 Hz 以上，預設值不傷人聲 |
| **響度正規化** | 兩階段 loudnorm | 整體太小聲；與燒錄時的響度正規化同一引擎 |

勾選項目與強度自動記憶；修完可對修復版再跑一次健檢比對。CLI：`python main.py --audiofix 影片.mp4`（依記憶的設定批次修復，免轉錄）。

### 分段音量一致性一鍵拉平（v1.24.0 起）

整體響度正常，不代表**每一段**都一樣大聲——收音距離忽遠忽近、不同場景／不同麥克風剪接在一起、外景風切偶爾蓋過人聲，都會讓觀眾一路調音量調到煩。既有的「整體響度」檢查只看全片平均，抓不出這種「忽大忽小」的段落級落差，因此健檢視窗新增「**分段音量一致性**」分析：

- 把影片切成固定長度的分段（預設 20 秒，可調 10~60 秒），逐段量測實際響度（LUFS），再與**整支影片的中位數響度**比較（不是對照 -14 LUFS 這種固定絕對值，因為每支影片的錄音環境本來就不同）——與中位數相差超過門檻（預設 3 LU，可調 1.5~8）即標記為落差過大的段落
- 「**拉平音量落差**」只調整被標記段落的音量增益，其餘段落與畫面完全不動——採音訊獨立處理（trim＋增益＋重新接回），畫面軌整段直接複製，不重新編碼畫面也不會有影音不同步風險；健檢沒找到落差過大的段落時按鈕維持停用，不會產生無意義的輸出檔
- CLI 新增 `--volumecheck`（輸出「檔名_音量一致性.txt」）與 `--volumefix`（拉平落差過大的段落並輸出「檔名_音量平衡.mp4」，沒有偵測到落差時單檔略過並提示），可與 `--audiocheck`／`--videocheck` 併用

## 品牌套版：片頭片尾接續與浮水印（v1.14.0 起）

調研發現創作者最常抱怨的重複工作之一，就是**每支影片都要重複手動加一次片頭片尾、調一次浮水印位置**——工具列的「**品牌套版**」把這兩件事收進設定檔一次設好，之後每支影片按一下即可套用，不必再進剪輯軟體重複同一套操作。

- **片頭／片尾一鍵接續**：設定片頭、片尾影片路徑（可只設定其中一項），輸出時自動接到來源影片前後。尺寸、畫面更新率、音訊格式不一致時自動正規化，避免黑畫面或比例跑掉；沒有音軌的片頭／片尾（常見的純動畫 bumper）會自動補上靜音音軌，不會因此無法接續。
- **浮水印／Logo 自動疊加**：設定圖片後，可調位置（左上／右上／左下／右下／置中）、大小（相對畫面寬度 5~50%）、透明度（10~100%）與邊緣留白，全片皆有效果。只用浮水印（不接片頭片尾）時保留音軌直接複製，不做無謂的重新編碼。
- 兩者可各自單獨使用，也可同時套用（合併成同一次 ffmpeg 執行）；輸出檔為 `素材_套版.mp4`。
- 所有設定自動記憶在 `config.json`；CLI：`python main.py --branding 影片.mp4` 套用已設定的內容（免開視窗，未設定任何一項時單檔略過並提示）。

## 一、下載與安裝

1. 前往本專案的 **Releases** 頁面，下載最新版的 `SRT-Subtitle-Generator.exe`。
2. 此為免安裝程式，下載後直接雙擊即可執行。
3. 首次執行會在程式所在資料夾自動建立 `config.json`（保存個人化設定）。

### 必要元件：ffmpeg（v1.12.0 起可一鍵自動安裝）

本程式的音訊解碼與語音轉錄皆依賴 **ffmpeg**。**最簡單的安裝方式：什麼都不用先做**——程式偵測不到 ffmpeg 時（審片助手、音訊健檢等視窗會顯示黃色提示條，錯誤視窗也會提供按鈕），按「**自動安裝 ffmpeg**」即可：

- 程式自動下載（約 80~100 MB，只需一次）並安裝到程式自己的資料夾
- **免管理員權限、不需要設定 PATH**，裝完立即可用、下次啟動自動生效

偏好手動安裝（或公司網路擋下載）時：

1. 至 [gyan.dev](https://www.gyan.dev/ffmpeg/builds/) 下載 release-essentials 壓縮檔。
2. 把其中的 `ffmpeg.exe` 與 `ffprobe.exe` 放到程式資料夾的 `tools\ffmpeg\bin\` 內（免設定 PATH）；或依傳統做法把 `bin` 資料夾加入系統環境變數 `PATH`。
3. 重新開啟本程式即可。

未安裝 ffmpeg 時，「文字稿對齊」「本地轉錄」「字幕燒錄」「粗剪／精彩合輯輸出」「音訊健檢」「封面候選」與審片助手的音量能量分析皆無法使用（審片的精彩偵測會退化為純文字訊號）。

### 自動更新

本程式（v1.1.0 起）內建自動更新：

- 每次啟動時會於背景向 GitHub 檢查是否有新版本。
- 偵測到新版時會跳出視窗詢問，同意後自動下載並替換程式檔。
- 更新完成後，關閉並重新開啟程式即可套用新版。
- 無網路或連線失敗時會自動略過，不影響程式使用。

## 二、三種運作模式

### 模式一：音訊轉錄

匯入影片／音訊檔，由系統自動產生逐字稿與時間軸。轉錄引擎有兩種選擇：

- **OpenAI API**（免安裝，最簡單）
- **本地 Whisper**（免費、可離線，但需自行安裝，見下方第三節）

### 模式二：文字稿對齊

貼上現成的逐字稿，系統會借用語音辨識取得音訊中「人聲」的時間軸（會自動忽略背景音樂），再把文字稿依語音長度與停頓分配到對應的時間點，讓字幕只落在有人聲的區段。

由於改用語音辨識偵測人聲，此模式同樣需要可用的語音辨識引擎（本地 Whisper 或 OpenAI API），設定方式與模式一相同，見下方第三節。

### 模式三：手動字幕模式

不經語音辨識，從零開始手動建立字幕：按「新增字幕」逐句輸入文字與起訖時間，適合無人聲素材、歌詞字幕或需要完全手工控制的情境。建立後同樣可使用匯出與燒錄功能。

## 三、語音辨識引擎設定（模式一與模式二皆會用到）

### 方式 A：使用 OpenAI API（推薦給一般使用者）

1. 切換到「模式一」。
2. 在「轉寫設定」勾選 **改用 OpenAI API**。
3. 於「API 金鑰」欄位填入你的 OpenAI API Key。
4. 選擇生成字幕即可，無須安裝任何額外程式。

### 方式 B：使用本地 Whisper（免費、可離線）

由於本程式為輕量版 exe，**並未內建 Whisper**。exe 是封閉環境，無法直接讀取你用 pip 安裝的套件，因此需採「外部 Python」方式串接：

#### 若你尚未安裝 Whisper

1. 安裝 [Python](https://www.python.org/downloads/)（3.9 以上版本），安裝時勾選 **Add Python to PATH**。
2. 開啟命令提示字元，執行：
   ```
   pip install openai-whisper
   ```
3. 確認 ffmpeg 已安裝（見第一節）。
4. 回到本程式「轉寫設定」的 **本地 Python** 欄位：
   - 留空：程式會自動偵測系統 PATH 上的 Python。
   - 或按「瀏覽...」指向該 Python 的 `python.exe`（通常位於
     `C:\Users\你的帳號\AppData\Local\Programs\Python\PythonXX\python.exe`）。
5. 之後選擇生成字幕，程式即會透過該 Python 執行 Whisper 轉錄。

#### 若你已經安裝過 Whisper

直接在「本地 Python」欄位按「瀏覽...」，指向「當初安裝 whisper 的那個 Python 的 `python.exe`」即可，程式會自動使用它。

> 查詢 python.exe 位置：開啟命令提示字元輸入 `python -c "import sys; print(sys.executable)"`，顯示的路徑即是。

#### 本地模型選擇

「本地模型」可選 `tiny` / `base` / `small` / `medium` / `large`，模型越大越準確但越慢。模型會於首次使用時自動下載。

#### 語言選擇

「語言」欄位除 `auto`、`zh`、`en` 等代碼外，另提供 **`zh-TW`**。Whisper 本身只認 `zh` 且預設常輸出簡體中文；選擇 `zh-TW` 時，程式會以 `zh` 辨識並加繁體提示詞偏導，再自動把結果轉換為台灣繁體中文。需要繁體字幕時請選 `zh-TW`。

## 四、智慧斷句設定

「斷句設定」區塊可即時調整，兩種模式皆適用：

| 設定項目 | 說明 | 調整範例 |
|----------|------|----------|
| 中文單行上限 | 中文字幕單行最大字數，超過會自動斷行 | 手機直向觀看字幕常顯太長時，調小到 14～16 字；橫向大螢幕可放寬到 20 字以上 |
| 英文單行上限 | 英文字幕單行最大字母數 | 同上邏輯，手機觀看建議 30～36 字母 |
| 最短秒數 | 每句字幕停留在畫面上的最短時間（過短會自動延長） | 觀眾反映字幕一閃即逝時調大（如 1.5 秒） |
| 最長秒數 | 每句字幕停留在畫面上的最長時間（過長會自動裁切） | 長句被硬切太短時可調大（如 6～8 秒），但避免整段影片只有幾句字幕 |
| 停頓秒數 | 音訊中靜音多久才算一次「停頓」，作為斷句與時間對齊的依據 | 講話語速快、停頓短的內容（如遊戲實況）可調小（0.3～0.5 秒）讓斷句更即時；語速慢、常有思考停頓的內容可調大避免斷句過於破碎 |

斷句演算法會優先依句末標點切句，其次依句中標點切子句，避免單一字幕文字過長霸佔畫面。不確定該調多少時，先用預設值生成一次字幕，看實際效果哪裡不順眼（太長／太短／停留太久／太快消失）再針對性調整，比一開始就大幅更動更容易抓到合適的數值。

## 五、字幕視覺調整

「字幕視覺調整」面板可即時設定：

- **位置**：水平 X、垂直 Y 滑桿，或使用「頂部／中部／底部」快捷鍵。
- **字型**：下拉選單內建常見中英文字型；旁邊的「...」按鈕可開啟字型選擇器，
  從系統字型中搜尋，或按「從字型檔匯入」載入自己的 `.ttf` / `.otf` 字型檔。
- **字型大小**、**文字顏色**、**邊框顏色**、**邊框寬度**。
- **重點字上色**（v1.6.0 起）：勾選後填入詞彙（逗號或空白分隔，如自己頻道的產品名、「免費」「限時」等），燒錄影片與匯出 ASS 時這些詞會自動換色強調（預設金黃、可選色）——CapCut 風格的重點標記，免逐句手動處理。SRT／VTT 純文字輸出不受影響。

  **範例：** 帶貨直播剪輯常見句子「這個現在**免費**送，數量**限時**搶購」，只要在重點字欄位填入 `免費, 限時`，之後每一句字幕只要出現這兩個詞就自動變色，不必逐句手動上色；詞彙用逗號或空白分開即可一次填多個，長詞（如「破盤價」）會優先於短詞比對，不會被短詞截斷。想要不同影片用不同顏色（例如促銷用紅色、重點用金黃），改變「重點字顏色」即可，設定會隨樣式一起記憶。

- **動態字幕**（v1.7.0 起）：逐字動畫字幕，於燒錄影片與 ASS 匯出時生效，兩種模式：
  - **逐字上色（卡拉OK）**：整句顯示在畫面上，講到哪個字、哪個字就換色（顏色沿用「重點字顏色」）——觀眾的視線跟著語音走
  - **單字彈出**：畫面上只顯示當前講到的字詞，並帶輕微放大彈出動畫——Shorts／Reels／TikTok 最常見的字幕版式，搭配大字級（例如 48 以上）與畫面中央位置效果最好
  - 需要逐字時間軸，因此**只在「模式一：音訊轉錄」產生的字幕上生效**；手動字幕、文字稿對齊或編輯過的句子自動退回一般整句顯示，不會出錯
  - 審片助手輸出的直式短片若勾「燒錄字幕」，同樣套用此模式——單字彈出＋直式短片就是現成的 Shorts 成品

所有調整（含重點字上色，v1.6.1 起）都會即時反映在「即時字幕預覽」畫面上，改詞彙或顏色不必先燒錄就能看到效果（動態字幕的逐字動畫屬於影片時間軸效果，預覽維持整句顯示，實際效果以燒錄輸出為準）。

### 習慣設定（樣式組合）

「習慣設定」可儲存多組樣式組合（包含字幕樣式與斷句設定）：

- **另存新樣式**：將目前所有設定存成一組新樣式並命名。
- **更新目前樣式**：以目前設定覆寫選取中的樣式。
- **刪除**：移除選取的樣式。
- 透過下拉選單可隨時切換不同樣式組合。

## 七、生成與匯出

**建議直接使用「一鍵完成」**（見開頭「快速上手」），生成、匯出、燒錄一步到位。以下為需要逐句檢查、微調時的手動流程：

1. 選擇模式、匯入檔案（模式二另需貼上文字稿）。
2. 按「開始生成字幕」，狀態列會顯示進度。
3. 生成完成後，字幕清單會列出每一句字幕，點選任一句可在預覽畫面中檢視，雙擊可編輯。
4. **校對**：同一個錯字整集重複出現時（人名、產品名、同音字），按「**尋找取代**」（v1.7.0 起）一次修正——「找下一個」逐句檢視、「取代目前」逐句確認、「全部取代」一鍵修完並回報次數；對話框開著仍可操作清單。
   - **自動修正詞庫（v1.8.0 起）**：對話框下方按「**把目前取代存為規則**」，這個錯字之後**每次生成字幕都會自動修正**，不必每集重修。語音辨識對特定人名、產品名的錯法通常很固定，累積幾條規則後校對量會明顯下降；規則可隨時在清單中刪除，重存同一錯字則更新規則。
5. 按「匯出 SRT／VTT／ASS／TXT」選擇儲存位置輸出字幕檔，或按「燒錄字幕到影片」輸出硬字幕影片。

### 字幕翻譯：一鍵雙語字幕（v1.18.0 起）

YouTube 的自動字幕功能無法輸出雙語軌，超過三分之二的觀看時數卻來自創作者所在地區以外——生成字幕後，按字幕清單下方的「**翻譯字幕**」即可一鍵翻譯：

1. **選目標語言**：11 種語言可選（英/日/韓/繁中/簡中/西/法/德/印尼/越南/泰）。
2. **選模式**：「雙語（原文＋譯文上下行）」讓每句字幕顯示原文與譯文兩行；「僅保留譯文（取代原文）」直接用譯文取代原字幕（可重新生成復原，不影響原始素材）。
3. 按「開始翻譯」。**需要 OpenAI API 金鑰**——沿用「轉寫設定」裡已填的那一把，不必再另外申請，按用量計費。
4. 翻譯完成後自動套用到字幕清單，可再用「尋找取代」校對；雙語行匯出與燒錄時分兩行顯示。

**譯文由 AI 產生，建議翻譯後抽查幾句**，尤其是人名、專有名詞與語氣是否恰當。另外，逐字動態字幕（卡拉OK／彈出字模式）在翻譯後會自動退回整句顯示——翻譯後的文字與原本的逐字時間軸已經對不上，直接顯示整句字幕最穩妥。

### 匯入既有字幕檔（v1.19.0 起）

本工具原本只能「匯出」字幕，手上已經有的字幕檔——下載的 YouTube 自動字幕、其他工具產出的檔案、舊專案留下的字幕——完全進不了工具，只能開記事本手動改。現在字幕清單下方多了「**匯入字幕**」按鈕，選取 .srt／.vtt 檔即可直接載入，接上編修、樣式、翻譯、燒錄整條既有管線。

**典型工作流程**：下載 YouTube 自動字幕 → 匯入本工具修正錯字（尋找取代）→ 翻譯成雙語字幕 → 燒錄成硬字幕影片（TikTok／Reels 等平台不支援外掛字幕檔，這是唯一選項）。

1. 按「**匯入字幕**」選擇 .srt 或 .vtt 檔；目前清單非空時會先確認是否取代。
2. 匯入成功後狀態列顯示「已匯入 N 句字幕（略過 M 段無法解析、編碼 X）」，字幕清單與預覽同步更新。
3. 之後即可比照一般生成結果操作：尋找取代校對、翻譯字幕、調整樣式、匯出其他格式或燒錄硬字幕。

**格式容錯細節**：
- **YouTube VTT 行內標記**：自動清除逐字時間戳 `<00:00:01.500>`、顏色／語者標籤 `<c>`、`<v Speaker>`，以及 `<i>`／`<b>`／`<u>`／`<font>` 等常見標記與 `{\an8}` 等 ASS 覆寫碼。
- **編碼自動偵測**：依序嘗試 UTF-8（含 BOM）／繁體 Big5 系列（cp950）／簡體（gb18030），Windows 上常見的非 UTF-8 字幕檔不會變亂碼。
- **略過壞區塊不中斷**：索引行可省略、時間軸容忍逗號或點分隔的毫秒、CRLF／CR 換行皆可解析；單一區塊格式有誤只略過該段並計入略過數量，不會讓整份檔案匯入失敗。

**CLI**：`python main.py --subs 影片.srt --burn 影片.mp4` 可跳過語音辨識，直接用既有字幕檔匯出其他格式並燒錄硬字幕（見下方命令列批次模式）。

### 字幕健檢：閱讀速度與行數（v1.20.0 起）

字幕檔案審核最常見的退件原因就是「觀眾根本來不及讀完」——業界常用 CPS（每秒字元數）當量尺，Netflix 成人內容上限 20、BBC 建議 15 以下。本工具生成字幕時雖然有斷句規則限制單行字數，但翻譯（雙語內容變兩倍長，時間軸卻沒變）、匯入既有字幕檔（品質不明）、手動新增或編輯的字幕都可能產生從未檢查過的過快字幕。

字幕清單下方按「**字幕健檢**」，掃描目前清單（不論字幕從何而來）並標出五類問題：

| 檢查項目 | 內容 | 預設門檻 |
|----------|------|----------|
| **閱讀速度過快** | 每秒字元數（CPS）超過門檻 | 17 字/秒 |
| **顯示時間過短** | 單句顯示秒數太短，來不及注意到 | 0.8 秒 |
| **行數過多** | 單句超過建議行數 | 2 行 |
| **單行過長** | 單行字元數超過建議寬度 | 21 字 |
| **字幕重疊**（v1.23.0 起） | 前後兩句時間軸重疊 | 有重疊即標記 |

- 門檻皆可在對話框調整並自動記憶（例如面向兒童或需要精讀的教學內容可調得更嚴格）。
- 按「**一鍵延長過快字幕**」：把 CPS 超標或顯示過短的句子，在**不與下一句重疊**的前提下自動延長顯示秒數（只調整時間軸，不改動文字內容）；下一句銜接太緊、沒有空檔可用時保留原樣，不會強行製造新的重疊，這時建議改為精簡文字內容。
- 按「**一鍵修復重疊**」（v1.23.0 起）：截短較早一句的結束時間消除重疊；起始時間相同或反序、單靠截短無法消除時，較早一句改保留極短長度、較晚一句整段順延並保留原本時長不變。**這是匯入既有字幕檔與手動編輯特別需要的檢查**——生成字幕（模式一／模式二）內建正規化已保證不重疊，但匯入檔案品質不明、手動編輯也未曾檢查起訖時間是否與相鄰句子衝突，時間軸重疊常導致 YouTube 等平台匯入失敗或播放異常。
- CLI：`python main.py --subcheck 影片.mp4` 輸出「檔名_字幕健檢.txt」（含重疊檢查），可與一般轉錄／對齊模式或 `--subs` 併用（`--review` 等不產生字幕的模式無效果）；實際修復請於 GUI 操作。

### 全片停頓自動跳剪（v1.21.0 起）

創作者社群公認「剪掉停頓」是初剪最花時間、最想自動化的一步——本工具已有的「一鍵去頭尾」只處理開頭結尾廢秒，中段每一句換氣、思考停頓仍要手剪。

字幕清單下方按「**自動跳剪停頓**」：依目前字幕的時間軸找出句與句之間過長的停頓，一次剪掉整支影片的冷場——**字幕時間軸同步重新對齊**，剪完不必再手動調整字幕。

- 先按「**預覽跳剪點**」（純分析目前字幕，免呼叫 ffmpeg，瞬間看到偵測到幾處停頓、預估能省下多少秒數），確認合理後再按「**輸出跳剪版**」實際裁切
- 門檻皆可調並自動記憶：**最短停頓秒數**（達此長度才視為可跳剪的冷場，預設 1.2 秒）、**緩衝秒數**（剪點兩側各保留的秒數，避免斷得突兀，預設 0.15 秒）、**安全上限**（跳剪總長度超過影片長度的此比例時自動中止，防止門檻設太低誤剪，預設 60%）
- 輸出 `素材_跳剪.mp4`＋時間軸已對齊的字幕檔（同資料夾）
- CLI：`python main.py --jumpcut 影片.mp4`，可與一般轉錄／對齊模式或 `--subs` 併用；`--burn` 燒錄的仍是原始（未跳剪）影片，兩者暫不會自動串接

### 重複片段偵測與剪除（v1.22.0 起）

同一句話講了好幾次、要手動翻逐字稿找出前面講壞掉的版本剪掉——這是初剪另一個吃時間的步驟。

字幕清單下方按「**重複片段偵測**」：找出同一時間窗內文字高度相似的句子（同一句話的前後幾次嘗試），只保留最後一次。**這裡動的是實際講話內容，假陽性風險比純靜音的跳剪高**（例如刻意重複的口號、報數測試麥克風），因此設計為先列出候選逐項勾選確認，才真正剪：

- 「**偵測重複片段**」（純分析目前字幕，免呼叫 ffmpeg）列出候選清單，預設全選，可自行取消勾選誤判項目，再按「**剪掉勾選的重複片段**」實際裁切
- 門檻皆可調並自動記憶：**相似度門檻**（兩句文字達此相似度才視為同句重講，預設 72%）、**比對時間窗**（只比對此秒數內的句子，間隔太遠不算重錄，預設 25 秒）、**剪點外擴秒數**（連同前後的吸氣停頓一起剪掉，預設 0.2 秒）
- 剪完影片同步把字幕時間軸重新對齊、被剪掉的句子從清單移除；輸出 `素材_去重複.mp4`＋對齊後的字幕檔
- CLI：`python main.py --retakes 影片.mp4` 只輸出候選清單「檔名_重複片段.txt」（不自動剪）；搭配 `--retakes-cut` 才會實際剪掉全部候選（命令列無法逐項確認，建議先用 `--retakes` 看過候選清單再決定）

## 九、常見問題

**Q：點「開始生成字幕」後出現「找不到 ffmpeg」？**
A：請依第一節安裝 ffmpeg 並加入系統 PATH。

**Q：本地轉錄出現「找不到可用的本地 Whisper」？**
A：請依第三節方式 B 安裝 Whisper，並在「本地 Python」欄位指向正確的 python.exe，或改用 OpenAI API 模式。

**Q：視窗內容顯示不下？**
A：視窗可自由縮放，內容超出時可使用右側／底部捲軸，或用滑鼠滾輪捲動。

**Q：字幕斷句太長或太短？**
A：於「斷句設定」調整單行字數上限與秒數限制後重新生成。

**Q：「一鍵完成」的檔案輸出到哪裡？**
A：預設輸出到來源影片所在的資料夾，檔名沿用來源檔名（如 `影片.srt`、`影片_subtitled.mp4`）。想集中輸出到固定資料夾，可在「自動化輸出」的「輸出資料夾」指定。同名檔不會被覆蓋，會自動加上 `(1)` 流水號。

**Q：把檔案拖到 exe 圖示上沒有反應？**
A：拖曳執行採用「自動化輸出」記憶的設定，請先開啟程式在「自動化輸出」勾選至少一種匯出格式（或燒錄），關閉程式後再拖曳。處理需要時間（轉錄與燒錄），完成後才會跳出結果視窗。

**Q：審片助手的「精彩片段」是怎麼判定的？標太多／太少怎麼辦？**
A：綜合四種訊號評分——說話音量能量、語速、情緒詞（哇、太扯、wow…）與驚嘆句，達門檻即標記。標太少請到「偵測設定」把**精彩敏感度**調高（如 1.5），標太多就調低（如 0.7）；也可在**自訂情緒詞**加入自己頻道常用的口號與梗詞，讓判定更貼合內容。設定會自動記憶。

**Q：同一支影片轉錄過了，換個功能又要重新等辨識？**
A：v1.4.0 起內建轉錄快取：同一檔案且轉寫設定相同時自動重用先前結果（例如審片分析完再一鍵上字幕，第二次瞬間完成）。快取存於程式資料夾的 `transcribe_cache/`，自動限量清理；不需要時可在「轉寫設定」取消勾選「重用轉錄快取」。

**Q：輸出的直式短片人物不在畫面中間？**
A：「裁切」版式預設焦點 0.5（畫面正中）。人物偏左調小（如 0.3）、偏右調大（如 0.7）後重新輸出；或改用「模糊背景」版式保留完整畫面。

**Q：響度正規化該用什麼目標值？**
A：一般影片用預設 **-14 LUFS**（YouTube 標準）即可。想在正規化後仍略高於平台基準，可用 -13～-11；Podcast 類口說內容常用 -16。設定會記憶，不需每次調整。

**Q：轉錄結果在同一時間點出現多句重複字幕？**
A：這是 Whisper 遇到靜音或背景音樂時的已知現象（幻覺迴圈），v1.4.0 已加入三層自動去重防護。若仍遇到，可回報 issue 並附上來源音訊特徵（如長靜音、純音樂段）。

**Q：動態字幕（卡拉OK／單字彈出）選了卻沒有效果？**
A：動態字幕需要逐字時間軸，只在「模式一：音訊轉錄」產生的字幕上生效；手動字幕、文字稿對齊或編輯過文字的句子會自動退回一般整句顯示。另外效果只出現在**燒錄影片與 ASS 匯出**——「即時字幕預覽」與 SRT／VTT 輸出維持整句。若整支影片都沒有效果，請確認字幕是本次以模式一生成的（重新按「開始生成字幕」即可）。

**Q：尋找取代會改到時間軸嗎？改錯了怎麼辦？**
A：尋找取代只改文字，時間軸完全不動。「全部取代」前可先用「找下一個」逐句檢視命中的句子；若取代錯了，把「尋找」與「取代為」兩欄對調再全部取代一次即可還原。

**Q：每集都要重修同樣的錯字（人名、產品名），有辦法記住嗎？**
A：有（v1.8.0 起）。在「尋找取代」填好錯字與正確字後，按下方「**把目前取代存為規則**」——之後每次生成字幕（含一鍵完成與 CLI 批次）都會自動套用，不必再手動修。規則清單就在對話框下方，可隨時刪除或重存更新。

**Q：背景音樂較大聲的素材，精彩片段是不是標得怪怪的？**
A：v1.8.0 起音量分析預設聚焦人聲頻帶（150～4000 Hz），配樂鼓點不再干擾精彩判定，直接重新分析即可。若素材本身以音樂為主體（樂器演奏、DJ），到「偵測設定」關閉「音量聚焦人聲頻帶」。

**Q：勾了「剪除口頭禪字」，粗剪聽起來會不會很跳？**
A：有三層保護：太短的口頭禪（<0.12 秒）不剪、剪點向內縮小緩衝不切到相鄰字、剪除後過短的殘片自動捨棄，多數口播素材效果自然。若素材語速很快、逐字跳剪頓挫感明顯，取消勾選改回整段取捨即可；也可改用 EDL 進剪輯軟體，剪點相同但可逐一微調。

**Q：發佈包的建議標題／標籤是怎麼來的？可靠嗎？**
A：標題取自「精彩分數最高的段落文字」——觀眾反應最大的內容通常就是影片賣點；標籤取自素材中實際講到的高頻詞（你的自訂情緒詞優先、中文高頻詞組、英文高頻詞）。它們是「初稿與靈感」而非成品：標題建議挑一個再潤飾、標籤上傳前自行增刪。想要更多候選，調大 `config.json` 裡 `publish` 的數量設定。

**Q：配樂助手輸出後，音樂閃避的效果聽起來還是不太對？**
A：先確認調的是哪個方向的問題——講話時**音樂還是蓋過人聲**：調高「閃避強度」；閃避**忽大忽小很突兀**（例如講話中間有短暫停頓就跳回原音量）：調低「閃避強度」或調高「閃避靈敏度」數值讓觸發沒那麼敏感；整體**音樂太大聲或太小聲**（跟閃避無關）：直接調「音樂音量」。三個旋鈕互相獨立，一次只調一個比較容易聽出差異。

**Q：審片助手輸出的 EDL 怎麼用？**
A：在 Premiere Pro 選「檔案 → 讀入」、DaVinci Resolve 選「File → Import → Timeline」載入 `.edl`，再連結原始素材，時間軸就是保留段落的順剪，可直接開始精剪。

**Q：粗剪影片／精彩合輯輸出後聲音或畫面不同步？**
A：粗剪採重新編碼（libx264＋AAC）確保剪點精準，一般不會不同步；若來源影片編碼特殊，建議改用 EDL 進剪輯軟體處理。
